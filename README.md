# ts-sddirecta

## 配布用exeの作成

```powershell
npm.cmd run build:exe
```

インストーラーを作成せず、`src-tauri/target/release/ts-sddirecta.exe` を生成します。
生成したexeを使用したいフォルダーにコピーして起動してください。
`panel_sd` には、起動したexeが存在するフォルダーを表示します。

実行先のPCには Microsoft Edge WebView2 Runtime が必要です。
画面用のHTML・CSS・JavaScriptはリリースビルドのexeに組み込まれるため、
`dist` や `node_modules` を配布する必要はありません。

## 開発用の起動

```powershell
npm.cmd run tauri -- dev
```

## 対象フォルダーの切替

通常権限でexeを起動してください。起動時はexeの保存先を対象にします。
画面へフォルダーをドロップするとそのフォルダー、ファイルをドロップすると
そのファイルの親フォルダーを対象に、起動時と同じ処理を実行します。

- 対象フォルダーの階層を表示します。dictionary用の `sdDirectaxs.csv` は
  対象フォルダー（ドロップ先）直下 → exeと同じフォルダー → exe直下のconfigフォルダー
  の順で探し、最初に見つかったCSVを読み込みます。
  `input` フォルダー、またはその直下のファイルをドロップした場合は、
  inputの親フォルダー → exe直下のconfigフォルダーの順でCSVを探します。
  この場合はinput直下・exe直下のCSVを追加では探しません。
  外部CSVが見つからなければ、exeに組み込まれた初期CSVを直接読み込みます。
  configフォルダーやCSVの自動作成・上書きは行いません。
- 対象フォルダー直下のファイルをdictionaryと照合します。
- dictionaryにはCSVの `E` より前の全領域を、1番目の要素（アクセスフラグ）とともに保持します。
  `A`・`R`・`W`・`N`・`0` を区別せず取り込み、画面の「SD MAP」に表示する範囲と件数も全領域から求めます。
  空行は読み飛ばし、`E` とそれ以降の行は取り込みません。
  ファイルが一致した領域はフラグ付きでsdloadingDictionaryに保持し、
  ファイルがない領域も元のdictionaryには残します。SD書込ボタンは全エリアSD書込として、`E` 以外の全フラグの一致ファイルを対象にします。
- 一致がない場合は、対象フォルダー内の `input` フォルダーを照合します。
  input内で一致した場合は、階層表示もinputへ切り替わります。
- 照合したフォルダー内で、拡張子を除くファイル名がdictionaryと一致する場合は、
  実際の拡張子付きファイル名を `panel_text` に赤字の警告で表示します。
  完全一致したファイルは警告せず、拡張子だけが異なるファイルはSD書込対象に含めません。
  対象フォルダーでの警告はinputの照合を妨げず、input内の警告には `input\` を付けます。
- CSVの読み込みとファイル照合は、起動時・ドロップ時・F5キー押下時に実行します。
  定期的な自動照合は行いません。F5では現在の対象フォルダーを維持し、
  CSVの探索・dictionaryの作成・ファイル照合・画面表示を更新します。
- CSVの確認・読込に失敗した場合は、前のdictionaryと一致結果をクリアします。

同じ親フォルダーにある複数ファイルはまとめてドロップできます。
対象が複数のフォルダーに分かれるドロップは、エラーを表示します。
管理者として起動した画面への、通常権限のエクスプローラーからのドロップは制限されます。

初期CSVはプロジェクト直下の `config/sdDirectaxs.csv` です。ビルド時にexeへ
組み込むため、このファイルを変更した場合はexeを再ビルドしてください。
配布時に元のCSVを添付する必要はありません。利用者による変更は、実行中のexeの
隣に `config/sdDirectaxs.csv` を配置して編集してください。

## アプリの情報

メニューの「バージョン情報」で実行中アプリの名前とバージョンを確認できます。
「アップデート確認」を押したときだけ、`shakenyanta/ts-sddirecta-releases` の最新リリースから署名付きの更新情報を取得します。起動時の自動確認は行いません。
更新がある場合はYES／Noで確認し、YESで更新exeをダウンロード・検証します。SD処理中は更新できません。
検証後にSD処理用プロセスとアプリを終了し、補助プロセスがexeを差し替えて同じ場所から再起動します。
CSV・config・input・outputなどの利用者データは変更しません。差し替えまたは新exeのプロセス起動に失敗した場合は旧exeへの復元を試みます。
正常更新後も、exeの隣の `.ts-sddirecta-update-*` フォルダーに旧exe（`previous.exe`）を残します。新バージョンの動作確認後、不要になった更新フォルダーは削除できます。
アプリ起動後の動作異常までは自動判定しません。exeの保存先への書込権限が必要です。開発ビルドでは更新確認のみ可能で、exeの差し替えは配布用ビルドでのみ動作します。
更新情報が未公開の場合は、最新版とは判定せず未公開と表示します。

## ポータブル版の更新ファイルの作成・公開

署名用の秘密鍵は `$env:USERPROFILE\.tauri\ts-sddirecta.key` に保管し、アプリへは対応する公開鍵 `src-tauri/update-public-key.txt` だけを組み込みます。
秘密鍵とパスワードはリポジトリやリリースへ公開しないでください。継続して更新を提供するため、秘密鍵をバックアップしてください。

1. `package.json`・`src-tauri/Cargo.toml`・`src-tauri/tauri.conf.json` のバージョンを同じ値に更新します。更新として配布するときは前回より大きい値にします。
2. PowerShellで `npm.cmd run release:prepare -- -Notes "今回の変更内容"` を実行します。秘密鍵を暗号化している場合は署名時にパスワードを入力します。
3. `dist-update/v<バージョン>/` の `ts-sddirecta.exe`・`latest.json`・`latest.json.sig` の3ファイルを確認します。
4. 配布用GitHubリポジトリで `v<バージョン>` タグのReleaseを作成し、3ファイルを同じ名前のまま添付して公開します。通常の最新版として公開し、ドラフト・プレリリースにはしません。

初回は利用者がexeを手動で配置して起動します。以降の新バージョンはアプリ内から更新できます。
`latest.json` にはバージョン・対象CPU・exeのURL・サイズ・SHA-256・変更内容を記録し、そのJSON全体をTauri CLIで署名します。
更新処理はインストーラーを使用しません。現在の配布スクリプトは1リリースにつき1つのWindows CPU構成を対象にします。
初回公開前に、テスト用フォルダーに置いた旧バージョンから新バージョンへの更新と再起動を確認してください。

## SD操作の権限

画面は通常権限のまま動作します。既存の `sd_read` / `sd_write` / `sd_fill` /
`sd_verify_fill` APIは、UAC確認後に同じexeの画面を持たない別プロセスで実行します。
操作を直列化し、別プロセスはアプリ終了まで待機して再利用します。初回のUAC承認後は、
同じプロセスが利用可能な間、再確認せずにSD操作できます。UACキャンセル時はSD操作を行いません。
通常終了時は接続を閉じ、SD操作プロセスの終了をWindowsで確認してから画面を閉じます。
終了待ちは別スレッドで行い、その間は新たなSD操作を受け付けません。終了確認に失敗した場合は画面に原因を表示します。

プロセス間の要求・結果は、プロセス起動ごとのランダムな認証情報を使った
ローカル接続で転送し、一時ファイルには保存しません。
1回の読込サイズは64MiBまで、転送するJSONは約256MiBまでです。

「SD書込」ボタンは、最新のCSV・対象ファイル・SDを検査し、進捗ポップアップを表示して書込・照合を実行します。確認一覧は表示せず、完了・失敗後も結果とログを保持します。「ログをコピー」でログをコピーし、「閉じる」でポップアップを閉じられます。処理中は閉じられません。起動時・ドロップ時・F5のCSV読込・フォルダー・拡張子警告は `panel_text` に残し、SD書込押下時はその末尾に `「SD書込」ボタン押下` を追記します。押下後に同じ読込・警告ログは再表示せず、最新CSV・ファイルの検査はバックエンドで行います。準備・書込・照合のログと結果はポップアップに表示します。
ファイルが領域より大きい場合は超過分を無視して注意を表示し、小さい場合は残りを `0xFF` で埋めます。
0バイトのファイルは領域全体を `0xFF` にし、ファイルがない領域は変更しません。
各ファイルの書込直後に、その対象領域の全バイトを読み戻して照合し、全ファイル書込後にも全対象を再読込して最終照合します。最終照合がすべて成功するまで正常完了にはしません。進捗率は書込・直後照合・最終照合の合計バイト数、完了件数は最終照合済みの件数です。カード全容量の故障診断は行いません。失敗時は後続を停止し、途中の書込は元に戻しません。検証範囲は [ベリファイ調査](docs/sd-verify-audit.md) を参照してください。

書込・照合はRust内で4MiB単位に分割し、書込・SD読込・期待値用の独立した3つの再利用バッファ（合計約12MiB）と一括処理中の単一ディスクハンドルを使用します。照合前の読込先は期待値のビット反転値で埋め、読み込まれなかった部分の残留データによる一致を防ぎます。
進捗ポップアップのログは最新行へ滑らかに追従します。過去のログへ手動でスクロールすると追従を停止し、最下部へ戻ると再開します。横スクロールの位置は保持します。Windows側でアニメーションの軽減を指定した場合は、スクロールのアニメーションを省略します。
ファイル本体は画面やプロセス間のJSONへ転送しません。進捗・完了件数・ファイル別と全体の所要時間を表示します。
ランプはSD操作用の管理者権限を示し、未取得は灰色、確認中は黄色、利用可能は緑色、取得・通信失敗は赤色です。
メニューの「ログ表示」で診断ログを `.txt` に関連付けられたテキストエディタで開きます。
「SD書込」を押すと、`panel_text`に`「SD書込」ボタン押下`を追加します。SD操作メニューの各項目と「outputを開く」も、ボタン名を含む押下ログを追加します。
診断ログは `%LOCALAPPDATA%\ts-sddirecta\logs` に起動セッションごとのUTF-8テキストとして保存します（LOCALAPPDATA未設定時は一時フォルダー配下）。自動削除は行いません。
SD準備・ロック・容量／形状取得・4MiB単位の読み書き・書込確定・管理者プロセスとの通信について、開始、終了、所要時間、エラーを記録します。各行に日本時間（+09:00）、Unixミリ秒、実行ID、処理ID、PID、スレッドIDを付け、各実行区間の終了時に準備・書込・直後照合読込・最終照合読込等の累積時間をSUMMARYへ記録します。定期的なドライブ確認は状態・エラー内容が変化した場合と長時間待機を中心に記録し、IPC応答待ちの重複行は省略します。
進捗画面には「H:を開いています」「SDをロックしています」などの処理名と経過秒数を表示します。処理が5秒以上継続すると応答待ち表示と警告ログを出します。監視通知は約250ミリ秒間隔で、SD処理の応答待ち中も更新します。この監視は自動タイムアウト・中断を行いません。
進捗が止まった場合は、実行IDと処理IDを使い、対応する終了／エラー行のない開始行や応答待ち警告を確認してください。ファイル名・パス・ドライブ・書込位置は記録しますが、ファイル本体や認証トークンは記録しません。
待機中は緑ランプでもドロップ可能です。処理中だけドライブ・フォルダー変更とF5を禁止し、終了操作も処理完了まで受け付けません。
書込元は書込先SD以外に置いてください。複数のドライブ文字を持つ同一ディスクへの一括書込は受け付けません。
詳細は [SD書込要件書](docs/sd-write-requirements.md) を参照してください。

メニューの「全エリアSD読み込み」は、SDからCSVの`E`より前の全領域を読み取り、exeと同じ場所の`output`フォルダーへ個別ファイルとして保存します。`A`・`R`・`W`・`N`・`0`の区別やPC側の同名ファイルの有無に関係なく、CSV記載順で保存します。CSVは「SD書込」と同じ探索規則で読み直します。
CSV・SD・保存先を検査し、SDの読み取りが可能であることを確認してから、`output`がなければ作成し、既存の場合は**直下のファイルをすべて削除**します。サブフォルダーとその中のファイルは残します。削除に失敗した場合は読み込みを停止します。`output`がリンクの場合や、CSVの出力名と同名のサブフォルダーがある場合も停止します。exeと`output`は読込元SD以外のディスクへ置いてください。
SDは読み取り専用で開き、既存の管理者プロセス内で4MiB単位に保存します。SD書込と共通のポップアップに、読込バイト数による進捗率、保存完了件数、ファイル名、ログと結果を表示します。処理終了後は「outputを開く」で保存先をエクスプローラーに表示できます。完了・失敗後も結果を保持し、処理中のドライブ変更・フォルダー変更・F5・終了・ポップアップを閉じる操作を禁止します。途中キャンセルはありません。エラー時は後続を停止し、保存済みファイルと途中のファイルは残します。削除済みの旧ファイルは復元しません。詳細は [SD読込要件書](docs/sd-read-requirements.md) を参照してください。

「全エリアSD FF初期化」は、選択したSDのCSVの`E`より前の全領域を、入力ファイルやアクセスフラグに関係なくCSV順で`0xFF`に書き換えます。**CSVに定義された先頭32KiB（`FILE-00.001`）も対象**で、その位置のパーティション情報なども上書きします。CSVの範囲外と領域間の隙間は保持します。現行の内蔵CSVでは94領域、40,611,328バイトです。対象範囲は実際に読み込んだCSVで決まります。
ボタン押下後に既存の進捗ポップアップを開き、CSV・SDを事前検査して自動開始します。入力ファイルや`output`は操作しません。単一のSDハンドルをロックして処理し、各領域の初期化・書込確定・全バイト照合後、全領域を再読込して最終照合します。最終照合の全件成功とSDハンドル解放後にのみ完了と表示します。進捗率は初期化・直後照合・最終照合の総バイト数、完了件数は最終照合済み領域数です。処理中の操作制限と結果保持はSD書込と共通です。エラー時は後続を停止し、書換え済みの内容は元に戻しません。exeは初期化対象SD以外のディスクに置いてください。詳細は [FF初期化要件書](docs/sd-ff-initialize-requirements.md) を参照してください。

ドロップやフォルダー切替だけでは、SD書込やUAC確認は発生しません。

## 検証

```powershell
npm.cmd test
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
npm.cmd run build:exe
```

自動テストはフォルダー解決・CSV参照先・input照合・画面切替時の競合・
SD操作の通信形式・接続再利用、メモリー上のディスクで切り詰め・補完・領域前後の保持・照合不一致、
画面の書込確認・操作制限・進捗・所要時間を検証し、実SDカードにはアクセスしません。
画面ビルド後に`node scripts/verify-panel-scroll.mjs --ff`を実行すると、Chromeで小さい画面のスクロールと、FF初期化ボタンから進捗・完了表示までを模擬APIで検証します。`--write`ではSD書込の実ボタンクリックと押下ログの記録を検証します。実SDにはアクセスしません。Chromeが既定の場所にない場合は、ブラウザーの実行ファイルのパスを引数へ追加してください。
配布前には通常権限での実際のドロップ受付、UAC承認・キャンセル、
SD操作APIの実機確認を行ってください。
