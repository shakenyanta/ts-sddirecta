# ts-sddirecta

## 配布用exeの作成

```powershell
npm.cmd run build:exe
```

インストーラーを作成せず、`src-tauri/target/release/ts-sddirecta.exe` を生成します。
生成したexeを使用したいフォルダーにコピーして起動してください。
`panel_sd` には、起動したexeが存在するフォルダーを表示します。

実行先のPCには Microsoft Edge WebView2 Runtime が必要です。
画面用のHTML・CSS・JavaScriptはリリースビルドのexeに組み込まれるため、
`dist` や `node_modules` を配布する必要はありません。

## 開発用の起動

```powershell
npm.cmd run tauri -- dev
```

## 対象フォルダーの切替

通常権限でexeを起動してください。起動時はexeの保存先を対象にします。
画面へフォルダーをドロップするとそのフォルダー、ファイルをドロップすると
そのファイルの親フォルダーを対象に、起動時と同じ処理を実行します。

- 対象フォルダーの階層を表示します。dictionary用の `sdDirectaxs.csv` は
  対象フォルダー（ドロップ先）直下 → exeと同じフォルダー → exe直下のconfigフォルダー
  の順で探し、最初に見つかったCSVを読み込みます。
  `input` フォルダー、またはその直下のファイルをドロップした場合は、
  inputの親フォルダー → exe直下のconfigフォルダーの順でCSVを探します。
  この場合はinput直下・exe直下のCSVを追加では探しません。
  外部CSVが見つからなければ、exeに組み込まれた初期CSVを直接読み込みます。
  configフォルダーやCSVの自動作成・上書きは行いません。
- 対象フォルダー直下のファイルをdictionaryと照合します。
- dictionaryにはCSVの `E` より前の全領域を、1番目の要素（アクセスフラグ）とともに保持します。
  `A`・`R`・`W`・`N`・`0` を区別せず取り込み、画面のSDエリア範囲と件数も全領域から求めます。
  空行は読み飛ばし、`E` とそれ以降の行は取り込みません。
  ファイルが一致した領域はフラグ付きでsdloadingDictionaryに保持し、
  ファイルがない領域も元のdictionaryには残します。SD書込ボタンは全エリアSD書込として、`E` 以外の全フラグの一致ファイルを対象にします。
- 一致がない場合は、対象フォルダー内の `input` フォルダーを照合します。
  input内で一致した場合は、階層表示もinputへ切り替わります。
- 照合したフォルダー内で、拡張子を除くファイル名がdictionaryと一致する場合は、
  実際の拡張子付きファイル名を `panel_text` に赤字の警告で表示します。
  完全一致したファイルは警告せず、拡張子だけが異なるファイルはSD書込対象に含めません。
  対象フォルダーでの警告はinputの照合を妨げず、input内の警告には `input\` を付けます。
- CSVの読み込みとファイル照合は、起動時・ドロップ時・F5キー押下時に実行します。
  定期的な自動照合は行いません。F5では現在の対象フォルダーを維持し、
  CSVの探索・dictionaryの作成・ファイル照合・画面表示を更新します。
- CSVの確認・読込に失敗した場合は、前のdictionaryと一致結果をクリアします。

同じ親フォルダーにある複数ファイルはまとめてドロップできます。
対象が複数のフォルダーに分かれるドロップは、エラーを表示します。
管理者として起動した画面への、通常権限のエクスプローラーからのドロップは制限されます。

初期CSVはプロジェクト直下の `config/sdDirectaxs.csv` です。ビルド時にexeへ
組み込むため、このファイルを変更した場合はexeを再ビルドしてください。
配布時に元のCSVを添付する必要はありません。利用者による変更は、実行中のexeの
隣に `config/sdDirectaxs.csv` を配置して編集してください。

## SD操作の権限

画面は通常権限のまま動作します。既存の `sd_read` / `sd_write` / `sd_fill` /
`sd_verify_fill` APIは、UAC確認後に同じexeの画面を持たない別プロセスで実行します。
操作を直列化し、別プロセスはアプリ終了まで待機して再利用します。初回のUAC承認後は、
同じプロセスが利用可能な間、再確認せずにSD操作できます。UACキャンセル時はSD操作を行いません。
通常終了時は接続を閉じ、SD操作プロセスの終了をWindowsで確認してから画面を閉じます。
終了待ちは別スレッドで行い、その間は新たなSD操作を受け付けません。終了確認に失敗した場合は画面に原因を表示します。

プロセス間の要求・結果は、プロセス起動ごとのランダムな認証情報を使った
ローカル接続で転送し、一時ファイルには保存しません。
1回の読込サイズは64MiBまで、転送するJSONは約256MiBまでです。

「SD書込」ボタンは、最新のCSV・対象ファイル・SDを検査し、書込内容の確認後に実行します。
ファイルが領域より大きい場合は超過分を無視して注意を表示し、小さい場合は残りを `0xFF` で埋めます。
0バイトのファイルは領域全体を `0xFF` にし、ファイルがない領域は変更しません。
書込後は全対象を読み戻して照合します。失敗時は後続を停止し、途中の書込は元に戻しません。

書込・照合はRust内で4MiB単位に分割し、約8MiBの再利用バッファと一括処理中の単一ディスクハンドルを使用します。
ファイル本体は画面やプロセス間のJSONへ転送しません。進捗・完了件数・ファイル別と全体の所要時間を表示します。
ランプはSD操作用の管理者権限を示し、未取得は灰色、確認中は黄色、利用可能は緑色、取得・通信失敗は赤色です。
待機中は緑ランプでもドロップ可能です。処理中だけドライブ・フォルダー変更とF5を禁止し、終了操作も処理完了まで受け付けません。
書込元は書込先SD以外に置いてください。複数のドライブ文字を持つ同一ディスクへの一括書込は受け付けません。
詳細は [SD書込要件書](docs/sd-write-requirements.md) を参照してください。

ドロップやフォルダー切替だけでは、SD書込やUAC確認は発生しません。

## 検証

```powershell
npm.cmd test
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
npm.cmd run build:exe
```

自動テストはフォルダー解決・CSV参照先・input照合・画面切替時の競合・
SD操作の通信形式・接続再利用、メモリー上のディスクで切り詰め・補完・領域前後の保持・照合不一致、
画面の書込確認・操作制限・進捗・所要時間を検証し、実SDカードにはアクセスしません。
配布前には通常権限での実際のドロップ受付、UAC承認・キャンセル、
SD操作APIの実機確認を行ってください。
