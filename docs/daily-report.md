# 日報解析

## 対象と表示

- プロ版のoutputタブで、説明が「自動日報2データ」と完全一致する行の「日報解析」を押すと別ウィンドウを開く。
- 対象はexe隣の `output` 直下にある、押した行のファイル（例：`FILE-AT.001`）。Rust側でもプロ版を確認し、フォルダー外のファイル指定を拒否する。
- ファイルを読み取り専用で一度読み込み、その時点のデータで表示する。ファイルやSDは変更しない。読込上限は16MiB。同じファイルの画面が開いている場合はその画面を前面へ出す。再読込する場合は解析画面を閉じて開き直す。
- 「項番・桁数・名称・内容・詳細」の5列。初期幅は名称列256、内容列200、詳細列200。項番は連番、内容は1バイト2桁の大文字16進数で、先頭ゼロを保持する。長い内容は省略表示し、ツールチップで全文を確認できる。
- 乗車・降車・立寄の日時行は、詳細列に `2026年11月17日 08時25分` の形式で表示する。5バイトを日・月・年の下2桁・時・分のBCDとして解釈し、西暦は2000～2099年とする。不正なBCD・存在しない日付・時刻は「日時不正」とし、元の内容は保持する。
- 「■支払区分」の詳細列は `src/utils/dailyReport.ts` の `paymentTypeDictionary` で内容の16進コードを文言に変換する（例：01＝現収、09＝合計押無し、19＝置換（メータ操作））。添付で未定とされた区分も承認されたdictionaryに含め、未登録コードは「未定義」と表示する。日時・支払区分以外の詳細列は空欄。
- メイン画面と同じ配色・罫線・交互背景・文字サイズと列幅調整を共用する。切り替えても行数・列幅は変えない。
- データ末尾より下に空行の罫線・交互背景を表示しない。grid幅の上限は列幅の合計と枠線分とし、詳細列の右に余白を作らない。ウィンドウの初期サイズは758×810で、小さい画面では作業領域に収めてスクロール表示する。

## バイナリ構成

- 先頭3バイトを読み飛ばし、最初の `CE` を営業の開始とする。直後にCEがない場合は、検出した開始アドレスと注意を表示する。
- 立ち寄りなしはCEを含めて201バイト。立ち寄りは1件12バイト（経度4・緯度3・日時5）で最大3件。
- 格納順は「CE → 乗車12バイト → 立寄1～3（各12バイト）→ 降車12バイト → 人数・料金以降」。
- 次の開始位置は、現在のCEから201・213・225・237バイト後の4候補でCEを検出する。途中の任意のCEは区切りに使わない。候補が重複した場合は、その営業以降の解析を停止して理由を表示する。
- gridは「ヘッダ」から「予備」までの39項目を表示する。「自動日報スタートアドレス」「文字数」は表示しない。39項目のサイズ合計が201バイトで、予備は84バイト。営業の開始位置・データ長は解析用に保持する。

## 最終営業とチェックサム

- 次のCEが4候補のどこにもない場合は、同じ長さ候補の直後2バイトをチェックサム候補とし、残りがすべてFFまたはファイル末尾であることを確認する。
- チェックサム2バイトとFF領域から終端候補を一意に判定できる場合だけ最終営業を表示する。末尾がFFであるために区切りが判断できない場合や、不明な後続データがある場合は解析を停止する。
- `FC E6` は固定マーカーとして扱わない。チェックサムの計算方式は未確定のため、値を候補として表示し、検証済みとは扱わない。
- 営業データがファイル末尾にちょうど収まり、チェックサム領域がない場合は、その長さで表示して注意を付ける。短い・不正・形式不一致の営業は表示せず、それまでに解析できた営業を維持する。

## 操作

- 上部の上下SVGアイコンで前後の営業へ移動する。位置を「現在 / 解析できた件数」で表示し、営業を変えると降車表示へ戻す。
- 名称列の「降車:経度」の右横に「立寄り・上矢印・下矢印・件数」を横一列で配置し、「降車 → 立寄1 → 立寄2 → 立寄3」を切り替える。「立寄り」は青い背景と太字で強調する。立寄表示でも同じセル内に操作欄を維持する。存在する分だけ操作でき、名称と内容の3行以外は維持する。
- 立ち寄りなしの営業では、「立寄り」のラベル・上下アイコン・件数表示を非表示にする。移動先がないボタンは無効にし、アイコンにツールチップと読み上げ用の名前を付ける。
- 解析画面だけを閉じてもメイン画面とSDワーカーは終了しない。メイン画面の終了時には解析画面も閉じる。

## 確認範囲

自動テストでは立ち寄り0～3件、読取位置、前後移動、降車への復帰、候補重複、データ不足、異なるチェックサム値、ファイル読込失敗、ライト版の拒否を確認する。実データでのチェックサム検証と立ち寄りありの照合は、仕様・サンプルが得られた時点で確認する。
