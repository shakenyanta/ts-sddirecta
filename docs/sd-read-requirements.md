# 全エリアSD読み込みの要件・仕様（移植元ソース調査）

調査日：2026年10月27日

本書の第1〜8節は、移植元 SDDirectAXS の動作と問題点を整理した調査記録です。第9節は、その後に利用者と合意した移植先の仕様・実装です。実機のSDカードは操作せず、ソース調査と模擬SD・画面処理の自動テストで検証します。

## 1. 処理の目的

画面で選択したSDカードの、CSVに定義された各領域を読み取り、領域ごとのバイナリファイルとして保存します。

- データの向きは **SDカード → PCのファイル** です。
- 「全エリア」は **CSVの終端 `E` より前の全領域** を指します。SDカード全体のイメージを1ファイルにする処理ではありません。
- 読み込み対象の選別に、PC側の既存ファイルの有無やアクセスフラグを使用しません。
- この経路にSDへの書き込み、FF初期化、FAT変換、復号、ファイル形式変換はありません。`.HEX` などの拡張子でも生のバイト列を保存します。

## 2. ボタン押下からの呼び出し経路

```text
「全エリアSD読み込み」(IDC_BUTTON3)
  → OnButton3()
  → fopen("sdDirectaxs.csv", "r")
  → ParameterAndSDCardOpen(FP, &hFile)
  → 成功時のみ SDreadSetToFile(PARAMETER_ALLFILE, FP, hFile)
  → UpdateData(FALSE)
```

`PARAMETER_ALLFILE` は `0x11`、読み込みモードの `SDREADMODE` は `0` です。

根拠：移植元 `SDDirectAXS.rc:100`、`SDDirectAXSDlg.cpp:21–26, 111–126, 387–406`。

## 3. 開始条件とドライブ

1. 起動時に `GetLogicalDrives()` で列挙し、`GetDriveType() == DRIVE_REMOVABLE` のドライブを選択欄へ追加します。先頭の `--` が初期選択です。起動後の再列挙処理はありません。
2. ボタン押下時に、カレントディレクトリー相対の `sdDirectaxs.csv` を開きます。
3. ドライブ未選択の場合は「ドライブが選択されてません」を表示して停止します。
4. 選択した論理ドライブ `\\.\X:` を開き、`IOCTL_STORAGE_GET_DEVICE_NUMBER` で物理ドライブ番号を取得します。
5. 論理ドライブのハンドルを閉じ、`\\.\PhysicalDriveN` を開き直します。

CSVのアドレスは **物理ドライブ先頭からのバイト位置** です。パーティション先頭からの相対位置ではありません。

旧実装は共通のオープン関数を使うため、読み込み時も `GENERIC_WRITE | GENERIC_READ` と読み書き共有で開きます。権限昇格の処理はこの経路にありません。メディア容量、SDカード種別、選択後のメディア交換、領域が容量内かどうかの検査もありません。

根拠：移植元 `SDDirectAXSDlg.cpp:167–192, 664–762`。

## 4. CSVによる対象決定

通常行は以下の形式です。

```csv
フラグ,ファイル名,開始アドレス,終了アドレス
A,FILE-AA.001,00008000,000083FF
N,FILE-AE.001,0015FC00,00167BFF
```

| 項目 | 全エリアSD読み込みの動作 |
| --- | --- |
| フラグ | `E` 以外をすべて対象にする。`A`・`R`・`W`・`N`・`0` で選別しない |
| 終端 | フラグが `E` の行で終了。その行と後続行は出力しない |
| ファイル名 | 拡張子を含め、CSVの名前を出力名にする |
| アドレス | 16進数のバイト位置。開始・終了の両端を含む |
| 領域サイズ | `終了アドレス − 開始アドレス ＋ 1` バイト |
| 処理順 | CSV記載順。アドレス順への並べ替えはしない |

「選択エリアSD読み込み」で使う `A`・`R` の条件は、全エリア処理には適用されません。未知のフラグも、旧実装では `E` でなければ対象になります。

付属の `sdDirectaxs.csv` は、終端より前に **87領域（A：85、N：2）** あります。全領域が512バイト境界に整列し、`0x00008000` から `0x02037DFF` まで連続しています。正常に出力した場合の合計は **33,750,528バイト** です。先頭の `0x00000000–0x00007FFF` と最終領域より後ろは保存しません。この件数・範囲は付属CSVの値であり、固定要件ではありません。

根拠：移植元 `SDDirectAXSDlg.cpp:517–661, 778–810`、`sdDirectaxs.csv:1–88`。

## 5. 保存先と上書き

- 保存先は、カレントディレクトリー相対の `output\CSVのファイル名` です。保存先選択ダイアログはありません。
- `output` フォルダーを作成する処理はありません。あらかじめ存在し、書き込み可能である必要があります。
- 出力ファイルは `fopen(..., "wb")` で開きます。既存ファイルは確認なしで切り詰めて上書きし、存在しなければ新規作成します。
- CSVにないファイルの削除や、`output` 全体のクリアは行いません。
- カード種別の選択は読み込みに影響しません。`FILE-BA.001` も `output\FILE-BA.001` へ保存します。`cardkind` 配下への振り分けは書き込みモードだけの処理です。
- 同名の行が複数あれば、後の行が前の出力を上書きする構造です。重複名検査はありません。

根拠：移植元 `SDDirectAXSDlg.cpp:545–619, 810–827`。

## 6. 領域ごとの読み取り

1. `ファイル名 + SD読み取り中` を状態欄に表示します。
2. 出力ファイルを開き、`SetFilePointer` で物理ドライブの開始アドレスへ移動します。
3. `ReadFile` で512バイトずつ読みます。
4. 読んだデータを `fwrite` で出力します。末尾の残量が512バイト未満でもSDからは512バイト読み、ファイルには残量分だけ書きます。
5. そのファイルを閉じ、CSVの次の行へ進みます。
6. `E` 到達後、CSVとSDのハンドルを閉じ、「SD読み取り終了!!」を表示します。

正常時の出力サイズは領域サイズと一致します。0xFFの補完、内容の解析、保存後の照合は行いません。

処理はボタンイベント内で同期実行します。進捗率、件数、所要時間、キャンセル、専用進捗画面、処理履歴ログは実装されていません。

根拠：移植元 `SDDirectAXSDlg.cpp:764–900`。

## 7. エラー時の旧動作

| 条件 | 表示・動作 |
| --- | --- |
| ドライブ未選択 | 「ドライブが選択されてません」。開始しない |
| CSVオープン失敗 | システムメッセージを表示し、「パラメータファイルオープン失敗!!」で停止 |
| 論理ドライブオープン失敗 | システムメッセージを表示し、「指定ドライブ(論理)オープン失敗!!」で停止 |
| 物理ドライブ番号取得失敗 | システムメッセージを表示し、「物理ドライブ番号取得失敗!!」で停止 |
| 物理ドライブオープン失敗 | システムメッセージを表示し、「指定ドライブ(物理)オープン失敗!!」で停止 |
| 出力ファイルオープン失敗 | システムメッセージを表示し、CSVを閉じて即時終了。専用の失敗状態文字列は設定せず、SDハンドルも閉じていない |
| `ReadFile` が失敗 | CSV・出力ファイル・SDを閉じ、「SD読み込み失敗!!」で全体を停止 |
| `fwrite` が失敗 | CSV・出力ファイル・SDを閉じ、「ファイル書き込み失敗!!」で全体を停止 |

エラー後の再試行や次ファイルへの継続はありません。すでに保存したファイルと、失敗したファイルの途中までの内容は残ります。上書き前の内容へ戻す処理はありません。

根拠：移植元 `SDDirectAXSDlg.cpp:673–758, 812–887`。

## 8. 旧実装の不足と移植時の検討事項

以下は旧実装に不足している点です。旧動作を踏襲する確定要件としては扱いません。

| 旧実装の不足 | 移植時に検討する対策 |
| --- | --- |
| CSVのEOF・不正行・終端欠落を検出せず、文字単位で解析する | CSV全体を先に検査し、不正フラグ・アドレス・逆転・終端欠落などをエラーにする |
| ファイル名の固定長バッファ、パス逸脱、重複名の検査がない | 安全な出力名と保存先内のパスに限定し、重複名を検査する |
| SD容量や領域境界を検査しない | 全領域がメディア内に収まることを開始前に検査する |
| `SetFilePointer` の戻り値を確認しない | シーク失敗を検出して停止する。移植先では64ビットのアドレスを扱う |
| `ReadFile` の実読込バイト数 `tempreadbyte` を確認しない | 短い読み取りや0バイトを検出し、不足したバッファ内容を保存しない |
| 末尾も常に512バイト読み、セクターサイズを取得しない | 実際のセクター制約に合わせ、出力には定義領域内のデータだけを含める |
| `fclose` の失敗を確認せず、遅延した保存エラーを見逃す | 書込・フラッシュ・クローズまで確認して正常完了を判定する |
| 既存ファイルを即時上書きし、途中失敗で不完全ファイルが残る | 上書き確認の有無、一時ファイルからの置換、失敗時の保持・削除を決める |
| エラー経路にハンドルの閉じ忘れがある | 正常・異常・キャンセルの全経路でリソースを解放する |
| C標準ファイルI/Oの失敗にも `GetLastError()` を使う | 失敗した処理に対応するエラー情報と対象パスを表示する |
| 読み込みでも読み書き権限を要求する | 読み取り専用アクセスで成立する構成と、既存管理者プロセスの再利用を検討する |
| 同期処理で、キャンセルや詳細進捗がない | 既存SD書込と整合する操作制限、進捗、ログ、キャンセル方式を決める |

保存先・既存ファイルの扱い・進捗表示については、調査後に第9節の方針で合意し、実装しました。

## 9. 移植先の確定仕様と実装

### 保存先・初期化

- 保存先は **実行中のexeと同一フォルダーの `output`** に固定します。カレントディレクトリーや画面の対象フォルダーでは変わりません。
- `output`がなければ作成し、すでにある場合は **直下の全ファイルを削除**します。CSVに定義されていないファイルも削除対象です。
- サブフォルダーとその内部は保持します。サブフォルダーが出力名と衝突する場合は開始前に停止します。
- CSV・SD・保存先の事前検査後、管理者プロセスでも再検査し、読み取り専用でSDを開いて実際の読み取りに成功してから初期化します。事前検査やUAC確認で失敗した場合は削除しません。
- 初期化の削除に失敗した場合は停止します。初期化途中までの削除は元に戻しません。
- `output`やその直下にリンク・ジャンクションがある場合は停止します。出力名の重複、大文字小文字だけが異なる名前、予約名、パス逸脱も拒否します。
- exeと保存先が読込元SDと同じ物理ディスクにある場合は停止します。

### 対象と保存処理

- 「SD書込」と同じCSV探索規則を使用し、処理開始時と管理者プロセスで最新内容を確認します。CSV・SD情報が変わっていた場合は停止します。
- `E`より前の全領域をCSV順に保存します。PC側の一致ファイルの有無に依存しません。`FILE-BA.001`も同じ保存先です。
- CSVの終端欠落、不正アドレス、逆転、領域重複、SD容量外、出力名不備を検査します。
- 既存の管理者プロセスを再利用し、単一の読み取り専用SDハンドルと再利用バッファで最大4MiBずつ保存します。ファイル本体はJSONへ転送しません。
- 実際のセクターサイズに合わせて読み、ファイルへは指定領域のバイト列だけを保存します。短い読み取りや保存失敗を検出して停止します。
- ファイルへの保存と`sync_all`成功後に保存完了件数を加算し、SDハンドルを閉じてから全件完了を通知します。
- 途中失敗では後続を停止し、保存済みファイルと不完全ファイルを保持します。旧ファイルの復元は行いません。

### ポップアップと操作制限

「SD書込」と共通のポップアップに、保存先、対象件数、読込バイト数に基づく進捗率、保存完了件数、処理中ファイル、所要時間、ログ、完了・失敗を表示します。コピー・スクロール追従・完了後の結果保持も共通です。

読込ポップアップの「outputを開く」ボタンから、exeと同じ場所の保存先をエクスプローラーで開けます。処理中は無効とし、完了・失敗後に操作できます。保存先が存在しない場合や起動失敗時は、ポップアップのログに原因を表示します。

処理中はドライブ・対象フォルダー変更、F5、終了、ポップアップを閉じる操作を禁止します。既存SD書込と同様に途中キャンセルはありません。バックエンドも書込と共通の実行フラグで直列化します。

主な実装は `src-tauri/src/sd_read_batch.rs`、`run_sd_read`、`sd_worker::read_batch`、`BatchDisk::open_read`、`HomeView.vue`、`SdMenu.vue`です。

### 検証範囲

自動テストでは、全フラグ・CSV順・終端・不正出力名、複数チャンクと非整列領域の正確な出力、SDへ書き込まないこと、フォルダー作成、直下ファイルの削除とサブフォルダー保持、初回読込失敗時の旧ファイル保持、途中失敗の停止と完了件数を確認します。画面処理では一致ファイルがなくても読み込めること、保存先表示、進捗、操作制限、完了・失敗後の結果保持を確認します。

実機でのUAC、SD読込、抜去時の挙動、保存先のアクセス権・空き容量不足時のWindows応答は別途確認が必要です。
