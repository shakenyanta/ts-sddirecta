# 履歴タブの要件と段階的な実装計画

記録日：2026年11月11日

本書は、ドラッグ＆ドロップ履歴について相談した内容と追加候補を整理したものです。第1〜9段階の履歴の記録・表示・保存と復元・再読込・コピー・お気に入り・行削除・履歴クリアを実装しています。件数上限以降は未実装です。番号は依存関係を考慮した推奨作業順であり、各段階を個別に実装・確認してから次へ進みます。追加候補や未確定事項は、記載だけで採用済みと扱いません。

## 要望・確定事項

- ドラッグ＆ドロップした日時とフルパスを履歴タブに表示する。
- アプリを再起動しても履歴の日時とフルパスを保持する。
- フルパスのダブルクリックで、ドロップしたときと同じように `panel_sd` に反映し、ファイル情報を表示する。
- 日時列の見出しは「日時」とする。「ドロップ日時」は使用しない。
- 大事な行の誤削除を防ぎ、通常の履歴が増えても下に埋もれない仕組みを検討する。

## 画面・動作の提案

履歴タブの上部を「お気に入り」、下部を通常の「履歴」に分ける。お気に入りは削除保護も兼ね、独立した鍵の機能は設けない案とする。

| お気に入り | 日時 | フルパス | 削除 |
| --- | --- | --- | --- |
| ★ | 2026/11/11 14:32:08 | `C:\作業\案件A\input` | 無効 |
| ☆ | 2026/11/11 13:05:21 | `D:\受領データ\FILE-AA.001` | 削除ボタン |

- 通常履歴は新しい日時が上。日時・操作列は固定幅とし、パス列に残りの幅を使う。
- 長いパスは中央を省略して末尾を見せ、ホバーで全文を表示する。
- 表の上に「パスをダブルクリックすると再読込します」という案内と「履歴をクリア」ボタンを配置する。
- 上部のお気に入り領域は高さに上限を設け、内部でスクロールできるようにする。具体的な高さは画面確認で決める。
- 行削除・全件クリア・自動削除は元のファイルやフォルダーを削除せず、現在の `panel_sd` とファイル情報も維持する。

以下の各段階の詳細は実装案であり、未確定事項は末尾にまとめる。

### 3. 保存と再起動時の復元

- 状態：実装済み。基本要望。前提：1・2。
- 両版共通で、ユーザーごとのアプリ内ローカルストレージの専用キー `sddirecta-drop-history-v1` へ `{ version: 1, entries: [...] }` のJSONを保存する。フォルダー表示状態とは別キーとし、`.config` とCSV用 `config` は使わない。
- アプリデータ内の独立JSONファイルと比較し、既存の保存基盤を再利用でき、依存ライブラリ・Rustコマンド・一時ファイル管理・非同期の保存待ち行列が不要なローカルストレージを採用した。同期的な `setItem` で全体を置き換え、同じ画面内で保存順が逆転しないようにする。保存失敗時は以前の値を保持する。ブラウザーの記憶域消去やOS障害まで防ぐバックアップ機能は今回の範囲に含めない。
- 各ドロップを記録して読込を開始した直後に保存し、終了時だけの保存に依存しない。起動時はドロップリスナーの登録前に同期的に復元するため、復元処理が起動直後のドロップを上書きしない。
- `parseDropHistoryState` でバージョン、配列構造、UUID形式と重複、日時の整数・範囲、パス配列と文字列を検証する。元のID・日時・パス一覧の順序を維持し、パスの存在確認や再読込は行わない。保存データなしは通常の空履歴として扱う。
- 読込・検証失敗時は元データを保持し、その起動中は履歴の上書きを停止する。今回のドロップはメモリ内に記録して通常どおり処理し、保存されないことをログ欄と両版のフッターへ警告する。元データの修復や退避は自動実行せず、原因の解消後にアプリを再起動して読み直す。
- 保存失敗時もメモリ内の履歴と以前の保存値を保持し、フッターへ継続表示する。次のドロップ・お気に入り変更・行削除・履歴クリアで全履歴を再保存し、成功すれば警告を解除する。未実装の件数上限を先行導入せず、容量不足も保存失敗として扱う。
- 確認：形式検証2件と保存・復元の結合テスト4件を追加。両版間の復元、連続追加、起動中ドロップ、保存データなし、未知バージョン・破損・読込拒否時の元データ保護、保存容量不足時の以前の値の維持と次回追加での再試行を確認した。
- 検証結果：`npm.cmd run build` は成功。`npm.cmd test` は94件中93件成功で、既存のファイル選択テスト1件だけが引き続き失敗。`node scripts/verify-panel-scroll.mjs --history` はChrome上で66件を保存してページを再読込し、日時・パスの表示、保存済みID・順序を含むJSON全体の一致と警告が出ないことを確認して成功。実exeの終了・再起動と実際のドラッグ操作は未確認。

### 4. 履歴からの再読込
