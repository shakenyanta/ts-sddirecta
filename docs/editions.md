# ライト版・プロ版の開発方針

## 位置づけと実装状況

１つのリポジトリ・共通ソース・共通exeで両版を管理します。現在の機能がライト版の基準です。
版の判定・表示とライト版の開発起動を実装しています。SD MAPの「詳細」ボタンとアドレス範囲表示はプロ版専用です。
プロ版では `panel_base` の右側に `panel_option` を表示します。パネル全体に広がるファイル情報グリッドは、No・ファイル名・説明・個別情報・更新No・更新Ver・条件・車種の8列で構成し、選択列・更新日時列は設けません。「書き込み対象」と同じ対象ファイルを表示し、FILE-BMは各ファイルをパラメータ1・2の2行に展開します。No列には表示行に対して上から1で始まる連番を表示し、SD書込対象の件数・処理は実ファイル単位のまま維持します。説明列にはCSVの5列目を表示しますが、FILE-BMはパラメータ1・2の説明に分けます。個別情報列は下記の形式を表示し、更新No・更新Ver・条件・車種は後述のFILE-BC解析結果を表示します。下の余白は背景の罫線・縞模様で埋めます。背景はウィンドウやパネルのサイズ変更に追従し、実データが表示領域に収まらない場合だけ縦スクロールします。初期の幅比率は1:2で、間の `resizer3` を左右にドラッグして変更できます。初期ウィンドウの表示領域はプロ版1,000×600、ライト版300×350論理pxを基本とします。両版とも起動時に、表示倍率・タイトルバー・枠を考慮したウィンドウ全体がタスクバーを除くモニターの作業領域に収まるよう、必要に応じて縮小し、中央に配置してから表示します。画面情報の取得・補正に失敗した場合は、警告を診断ログに記録し、最大化して表示します。

両版とも、`panel_sd` と `panel_text` の初期高さは4：3です。メニュー・フッター・境界線を除く残りの高さを配分し、ウィンドウの高さ変更に追従します。境界のドラッグで配分を変更でき、変更後はその比率を維持します。

`panel_sd` の未選択行のフォルダー名をシングルクリックすると、その行を選択して既存のCSV探索・ファイル照合ルールで対象を読み直し、プロ版のgridを更新します。ツリーの階層・展開状態・スクロール位置は変更しません。フォルダー選択は両版共通で、ライト版にはgridを表示しません。SD処理中・読込中・終了処理中は選択を変更できません。

説明が省略・空欄（空白のみも含む）の場合は、同じファイル名の内蔵CSVの説明を補完します。外部CSVに説明があれば優先し、内蔵CSVに該当名がなければ空欄のままです。input表示時を含め、CSVの探索ルールは維持します。補完対象は説明文だけで、外部CSVの対象領域・件数・アクセスフラグ・開始／終了アドレス・アドレス範囲は変更せず、内蔵CSVだけにある領域も追加しません。起動・フォルダー切替・F5で再取得します。CSVの読み込み処理は両版共通で、ライト版のSD処理にも設定変更はありません。

個別情報は `ts-sddirect` の `getUniqueInfo` を基に、FILE-AAのローディング回数制限、FILE-BCの収録番号一覧とTS-MAINの数字付き名称全体への対応を追加しています。実際に照合されたフォルダー（対象フォルダーまたはinput）のファイルをRust側で解析します。F5の再読込時にも更新し、読込失敗時は空欄と診断ログで対応します。ライト版ではRust側で解析を実行しません。

| ファイル名（拡張子を除く） | 個別情報 |
| --- | --- |
| FILE-AA | 0xCE〜0xCFがFF FFなら「無制限」。それ以外は2バイトを4桁のBCDとして読み、先頭の0を省いたローディング回数制限を表示（01 00→100、00 99→99、00 00→0）。不正なBCD・データ不足は空欄 |
| FILE-BM | 先頭8バイトのHEX（空白区切り） |
| IM | 0xD7F0から14バイトの登録番号。領域がない場合は「登録番号なし」 |
| FILE-BA | 0x5Bの署名に対応するカード種別 |
| FILE-BC | 32バイトの各ブロックの先頭2バイトを文字列として取得し、ファイル内の順序・重複を維持して空白区切りで表示（30 31、30 32→01 02）。先頭2バイトがFF FF、続く2バイトが46 55（FU）以外、末尾の32バイト未満のブロックは無視。対象ブロックがなければ空欄 |
| TS-MAIN | HEXテキストからバージョンとFROMチェックサムを取得。片方だけ取得できた場合はその値 |
| TS-MAIN＋数字（.HEXのみ。TS-MAIN2・TS-MAIN3・TS-MAIN15など） | 0x1002の4バイトによるバージョンと末尾2バイトのHEX |
| TS-SUB21〜25 | HEXテキスト中の名称直後からバージョンを取得 |
| TS-DISP | HEXテキスト中でTS-SUB20を表す54532D5355423230を検索し、直後8文字からバージョンを取得 |
| TS-PRN | HEXテキスト中で末尾に半角空白2文字を含む「TS-PRN  」を表す54532D50524E2020を検索し、直後8文字からバージョンを取得 |
| TS-PRNSW | HEXテキスト中でTS-SUB26を表す54532D5355423236を検索し、直後8文字からバージョンを取得（10033000→100330_00） |

上記以外は空欄です。TS-MAINの後ろが半角数字だけの場合は、参照元のTS-MAIN2用の解析方法を使用します。TS-MAIN3Aなど数字以外が混ざる名前は対象外です。ファイル名・拡張子の大文字小文字は区別しません。数字なしのTS-MAINは従来のHEXテキスト解析を維持します。省略された個別情報はツールチップで全文を確認できます。
今後プロ専用機能を追加し、別途指示がない限り現在の機能は両版で維持します。

ファイル情報グリッドはHandsontableを使用せず、HTMLテーブルで表示します。参照元 `ts-sddirect` の列から選択・更新日時を除き、説明を3列目に配置し、個別情報の直後に更新Noを追加しています。外観は左側パネルと共通の11pxのゴシック体・淡い青系に統一しています。外側の余白は左・上0px、右・下3pxとし、グリッド外枠の左上には角丸を付けません。ヘッダー高は24px、行高は18pxです。個別情報列は先頭8バイトのHEXや14文字の登録番号が収まる168pxを確保し、更新No列は48px、説明列が残り幅を使います。狭いパネルでは最小幅520pxで横スクロールします。

開発部署はプロ版、営業・サービス部署・代理店はライト版を使用します。
使い分けは運用ルールで管理します。設定ファイルを用意すればプロ版になる方式であり、認証・ライセンスによる利用制限は設けません。

### 更新情報とファイルの警告

書き込み対象が0ファイルでgridが空の場合は、FILE-AA・FILE-BA・FILE-BCの確認・解析を行わず、関連する警告も表示しません。対象ファイルがある場合は以下の確認を行います。

プロ版では、gridと同じ対象フォルダー（input表示中はinput内）でFILE-AA・FILE-BA・FILE-BCを確認します。それぞれ存在しない場合・複数ある場合は、既存のログ欄に理由とファイル名を表示し、フルパスは表示しません。対象フォルダーのフルパスは診断ログに記録します。直下の通常ファイルを対象とし、.BAKとディレクトリは候補に含めません。FILE-AA・FILE-BAの警告はFILE-BCの解析を妨げません。

FILE-BCが1件だけ存在し、gridにも表示されている場合に限って解析します。複数ある場合は自動選択せず、未表示・読込失敗の場合も理由を警告します。解析できない場合は対応表から決まる更新Noだけを表示し、更新Ver・条件・車種は空欄にします。

| ファイル名（拡張子を除く） | 更新No |
| --- | --- |
| FILE-BM | 01（BM:パラメータ1）と02（BM:パラメータ2）の2行 |
| FILE-BO・FILE-BP・FILE-BQ・FILE-BR・FILE-BS・FILE-BU | 順に03・04・05・06・07・08 |
| IM・FILE-BW・TS-MAIN | 順に09・10・11 |
| TS-SUB21〜25・TS-DISP | 順に12〜16・17 |
| TS-PRN・TS-PRNSW | 順に18・19 |
| FILE-BI・FILE-BH・FILE-BV | 順に31・32・43 |

参照元と同じく名称末尾の数字も許容し、TS-MAIN2・TS-MAIN3も11に対応します。FILE-BM.001・.002・将来の.003はそれぞれ01・02の2行に展開し、同じ更新Noの重複を許容します。FILE-AA・FILE-BA・FILE-BCや対応表にないファイルには疑似番号を付けず、4列とも空欄とします。

FILE-BCは32バイト単位で読み、0〜1バイトの更新Noで対応付けます（位置は0始まり）。更新Verは4〜11バイトの8桁を6桁と2桁に分けてアンダースコアを挿入し、条件は12〜13バイト、車種は24〜25バイトのASCII文字列です。通常の0xFF埋めレコードは読み飛ばします。末尾の32バイト未満の余りも、すべて0xFFなら警告せず読み飛ばし、それ以外の値が含まれる場合だけ不完全なレコードとして警告します。不正な番号・値、空ファイル、レコード番号の重複も警告し、取得できない項目を空欄にします。番号重複は該当番号の3項目をすべて空欄にします。表示対象に対応する有効なレコードがない場合も警告します。

起動時・フォルダー切替・F5で更新し、以前の取得結果を残しません。解析と警告生成はRust側で行い、ライト版では実行しません。更新Ver列は値が収まる68pxです。

## 起動時の版の判定

| 実行方法 | 判定 |
| --- | --- |
| `npm run tauri dev`（標準のデバッグビルド） | 標準でプロ版 |
| `npm run dev:lite` | 子プロセスに `SDDIRECTA_DEV_EDITION=lite` を渡してライト版 |
| 配布用リリースビルド | exeの隣の `.config/edition.json` を参照 |

デバッグビルドでは開発用環境変数が `lite` の場合だけライト版、それ以外はプロ版です。配布用設定は読みません。
リリースビルドでは開発用環境変数を無視し、設定が `"edition": "pro"` の場合だけプロ版とします。
設定なし、または `"edition": "lite"` ならライト版です。不正・読込失敗時は理由を画面に表示してライト版にします。
設定はUTF-8（BOM付きも可）で、`edition` 以外のキーや未知の値は不正として扱います。

Rust側で起動時に一度だけ確定し、Vue側へ渡します。変更後は再起動が必要です。
ウィンドウタイトルは `ts-sddirecta pro` または `ts-sddirecta lite` とし、開発用の付記はしません。
バージョン情報では現在の版を表示し、デバッグビルドには「開発」を付記します。
画面側で判定結果を取得できない場合は警告を表示し、プロ専用機能を許可する状態にはしません。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src-tauri/src/edition.rs` | 版の判定・起動時の結果保持 |
| `src/editions/index.ts` | Rustからの取得と画面側の版情報の集約 |
| `scripts/dev-lite.mjs` | ライト版の開発起動 |
| `.config/edition.example.json` | ライト版を指定する設定サンプル |
| `.config/edition.json` | 配布先で使用する実設定（Git管理対象外） |
| `tools/pro-kit/.config/edition.json` | Git管理するコピー用のプロ版設定 |
| `tools/pro-kit/README.md` | プロ版への切り替え・ライト版へ戻す手順 |

画面やSD処理は共通です。版別のexe・Tauri設定ファイル・更新情報は作りません。
既存のCSV用 `config` と版設定用 `.config` は別のフォルダーです。

## 配布・更新

`npm run build:exe` で共通exeを作成します。GitHub Releasesの公開ファイルは従来の
`ts-sddirecta.exe`、`latest.json`、`latest.json.sig` の３つです。
バージョンと更新先は両版で共通です。

開発部署には、[プロ版への切り替えセット](../tools/pro-kit/README.md) を別途渡します。
アプリを終了してから `tools/pro-kit/.config` をexeの隣へコピーし、再起動するだけでプロ版になります。
既存の `.config` があれば `edition.json` だけをコピーし、ほかの設定は保持してください。
`pro-kit` フォルダーごとexeの隣に置くのではなく、次の配置にします。

```text
配布先/
├─ ts-sddirecta.exe
└─ .config/
   └─ edition.json
```

```json
{
  "edition": "pro"
}
```

プロジェクト直下の実設定 `/.config/edition.json` はコミットせず、コピー用の `tools/pro-kit/` はGit管理します。
コピー用セットは通常の配布物やリリース添付には含めません。配布スクリプトは３ファイルを個別に扱います。
ライト版へ戻す場合は、配置先の `edition.json` を `{"edition":"lite"}` に変更して再起動します。
更新処理はexeを差し替え、`.config` やCSV・input・outputを保持します。
既存ユーザーは設定がなければライト版になります。SD MAPの詳細表示以外の既存機能は維持されます。

## 配布用exeの動作確認

配布用exeの版判定を確認する場合は `npm.cmd run edition:test:prepare` を実行します。
ビルド後、Git管理対象外の `dist-update/edition-test/日時-識別子/` に同一exeを３つコピーします。
毎回別フォルダーを作成するため、既存の利用データや前回の検証フォルダーは上書きしません。

1. `lite/ts-sddirecta.exe`：設定なしで `ts-sddirecta lite`、詳細ボタンなし。
2. `pro/ts-sddirecta.exe`：プロ設定で `ts-sddirecta pro`、詳細ボタンあり。
3. proを終了せず `.config/edition.json` を `{"edition":"lite"}` に変更：起動中はプロ版のまま。
4. proを終了して同じexeを再起動：ライト版となり詳細ボタンなし。
5. `invalid/ts-sddirecta.exe`：不正設定でライト版となり、警告を表示、詳細ボタンなし。

検証ではSDへの書込・初期化・フォーマットを実行する必要はありません。

### 確認結果（2026-10-30）

v0.1.2のリリースビルドを上記の手順で実際に起動し、５項目すべてを確認しました。
プロ版では「詳細」を押してアドレス範囲が開くことも確認済みです。
３ケースのexeはSHA-256が一致しています。
検証用アプリは終了し、検証中に変更したproケースの設定は `pro` に戻しています。
SDへの書込・初期化・フォーマットと、GitHubへの公開は実行していません。

## 機能比較と今後の追加

| 項目 | ライト版 | プロ版 |
| --- | --- | --- |
| SD MAPの「詳細」ボタン・アドレス範囲表示 | 非表示 | 利用可能 |
| `panel_option`・左右の幅を変更する `resizer3` | 非表示 | 書き込み対象の連番・ファイル名・説明・個別情報をグリッドに表示（更新No・更新Ver・条件・車種は未連携） |
| その他の既存機能 | 利用可能 | 利用可能 |

SD MAPの詳細表示は画面内の表示切り替えであり、専用のRust処理はありません。
今後の追加時にも本書を更新し、画面側の利用可否を `src/editions/` に集約します。
Rust側の専用処理を伴う場合は実行も制限し、その他の既存機能が両版で維持されることを確認します。
未決定の機能差は独断で決めません。変更履歴は `CHANGELOG.md` の「未リリース」に記録します。
