# SDフォーマット機能の要件・実装仕様

作成日：2026年10月28日

メニュー「SDフォーマット」を実装しました。既存のSDドライブ選択と管理者権限プロセスを使い、確認画面の「開始」後にパーティション再作成とクイックフォーマットを行います。実機SDへのフォーマットは未検証です。

## 1. 目的

「全エリアSD FF初期化」後のSDカードを、Windowsで通常のファイル保存に使える状態にする。
以前のFAT・ファイルを復元する機能ではなく、パーティションと空のファイルシステムを新しく作る。
FF初期化を実行していないカードからも使用できる独立した機能とする。

付属CSVには物理ディスク先頭の `0x00000000–0x00007FFF` が含まれ、FF初期化でMBR等が失われる。そのため、既存ボリュームへのクイックフォーマットだけでなく、パーティションの再作成まで扱う。
FF初期化の対象はCSV定義領域だが、本機能は選択したカード全体の構成を作り直す。CSV・入力ファイルの有無に依存させない。

## 2. 実装範囲

| 項目 | 実装仕様 |
| --- | --- |
| 対応環境 | Windows 10/11。開発起動・配布用exeで同じ対象検査を適用する |
| メニュー | 既存メニューのSD操作欄に「SDフォーマット」を追加 |
| 対象 | 識別可能なSDカード／取り外し可能メディア。内蔵ディスク等を除外する |
| 方式 | 通常は単一パーティションを再作成してクイックフォーマット。Windowsがカード全体を単一ボリュームとして扱う場合は、そのボリュームをフォーマット |
| パーティション形式 | MBR。2TiB超とMBRで表現できない構成は事前に拒否。GPT・SDUCは非対応 |
| 使用容量 | 管理領域・配置調整を除いた利用可能な最大容量 |
| ファイルシステム | 取得した容量からFAT／FAT32／exFATを自動選択。形式の手動変更は行わない |
| ラベル | 任意入力、空欄可。半角英数字・空白・`_`・`-`で11文字以内。前後の空白は除去し、FAT／FAT32では大文字へ統一 |
| アロケーション単位 | 初期設定はWindowsの既定値。特定機器向けの固定値は追加要件として扱う |
| 初期実装に含めない機能 | CHS調整、上書きフォーマット、全セクターの消去・不良検査、旧ファイルの復元、SD Card Formatter完全互換 |

ファイルシステムは、実容量16MiB〜2GiBでFAT、2GiB超〜32GiBでFAT32、32GiB超〜2TiBでexFATを自動選択する。論理セクターサイズ512バイトのメディアを対象とする。
容量だけではカード規格を確定できない場合があるため、SD規格の容量区分とWindowsの作成条件を混同しない。
画像の約474.50MBのカードではFAT16を第一候補とし、対象機器がFAT16を必要とするか確認する。FAT32への一律固定はしない。
パーティション配置は1MiB境界に整列させ、クラスタサイズはWindowsの既定値を使う。特定機器との互換性は実機確認事項とする。

### 2.1 SD容量とフォーマット形式

SD規格と形式の関係は次のとおり。実装上の判定境界は前述の実バイト数を使う。動作確認済みの実機容量一覧ではない。

| カードの規格・容量区分 | 使用する形式 | 対応方針 |
| --- | --- | --- |
| SD：2GB以下 | FAT（FAT12／FAT16） | 本機能では16MiB以上を対象とし、約512MBクラスはFAT16を想定 |
| SDHC：2GB超〜32GB | FAT32 | 対応対象 |
| SDXC：32GB超〜2TB | exFAT | 対応対象。64GB・128GB等をFAT32へ変更する機能は初期実装に含めない |
| SDUC：2TB超 | exFAT | 非対応 |

上表のGB・TBはSD規格の容量区分を示す。画面に出る利用者領域の容量やカードの公称容量と、フォーマット後の使用可能容量は一致しない。
判定には既存の容量表示を丸めた文字列を使わず、実際に取得したバイト数を使う。規格情報を取得できる場合は併せて確認する。

### 2.2 容量に関する制限

- **上限**：SDXCの2TBクラスまでを対象とし、2TB超のSDUCは非対応とする。さらにMBRで実際に表現できる範囲内に限定し、2TiB（2,199,023,255,552バイト）を超えるディスクは非対応とする。パーティションの開始位置・長さがセクター数の上限に収まることも確認する。超過分を切り捨てて処理しない。
- **下限**：本機能の下限は16MiB（16,777,216バイト）。これ未満は書換え前に拒否する。Windows全体の最低対応容量を意味するものではない。
- **セクターサイズ**：論理512バイトを対象とし、論理4KiB等は書換え前に拒否する。
- **FAT32の扱い**：本機能では32GB以下のSDHC向けに使用する。Windowsのバージョン・呼出方法によって作成可能な上限が異なり得るため、「FAT32自体の上限が32GB」とは扱わない。大容量カードはexFATとする。
- **ファイル単体の上限**：FAT32では4GiB未満。4GiB以上のファイルを保存する用途はexFATを使う。これはカード全体の容量上限とは別の制限。
- **使用可能容量**：MBR・ファイルシステムの管理領域や配置調整により、カードの全容量より少なくなる。
- **機器側の上限**：Windowsで作成できても、使用機器やカードリーダーがその容量・形式に対応している必要がある。exFAT非対応の機器でSDXCが使用可能になることは保証しない。

範囲外の場合は理由を表示して開始しない。容量・ラベル・システムディスク等の検査は構成変更前に行い、Windowsの構成作成・フォーマット処理で発生したエラーは発生段階で停止する。後者は既存構成の削除後に発生する場合があり、元の構成の復元は行わない。

## 3. 対象カードの選択

1. **「SD書込」で使用しているSDドライブ選択欄を、そのままフォーマットでも共用する。** フォーマット専用の選択欄や、選び直す操作は追加しない。
2. 選択ドライブの検査・物理ディスクの特定は、既存SD操作の共通処理を再利用する。既存の対象保護も引き継ぎ、フォーマット用に同じ規則を重複実装しない。
3. フォーマット固有の検査として、指定形式で作成できることと、パーティション再作成の各段階で対象が同じカードであることを確認する。対象が変わった場合は停止する。

SDの検出は物理デバイスのリムーバブルメディア情報と容量を使い、ファイルシステムの有無・正常性を条件にしない。
ドライブ文字があるカードは従来どおり表示し、割り当てのないカードは同じ選択欄に「?:」と表示する。同じカードを重複表示しない。
未割当SDもフォーマット対象として選択できる。既存のSD読込・書込・FF初期化はドライブ文字のある対象で使用する。
検出によってWindowsのドライブ文字は変更しない。フォーマット完了時に空いている文字を割り当てるため、以前のH:に戻るとは限らない。

## 4. 画面と実行確認

メニュー押下で設定・確認ダイアログを開く。メニュー押下だけでは書き込まない。

- 対象カード、容量、ファイルシステム、ボリュームラベルを表示する。
- 「ボリュームラベル（11文字以内）」と入力欄を1行にまとめ、その下に「FAT簡易テスト(書込・読出・削除)」のチェックボックスを置く。狭い画面ではラベル行を折り返す。初期状態はチェックなしで、選択時だけテストファイルの作成・書込・読戻し・削除を行う。FAT32／exFATでも選択できる。
- 確認画面とフォーマットログの容量は、カード識別用に「512M」「8G」等の目安へ丸めて表示する。設定・範囲判定には取得した実バイト数を使う。確認画面の容量行に実容量のツールチップを付ける。
- データ消失の注意は設定欄の「このSDカードのデータはすべて失われます。」で表示する。
- 「開始」「キャンセル」を設け、開始操作時に対象を固定する。開始前のキャンセルは無変更で終了する。
- 完了画面の上部とログには、作成後の形式をFAT12／FAT16／FAT32／exFATで表示する。FATの種類はボリュームのブートセクターからデータクラスタ数を算出して判別し、容量だけでは推定しない。
- CSVがない・不正、対応入力ファイルがない場合でも、フォーマットの対象検査が通れば利用できる。
- SD処理・アプリ更新・終了処理中は開始できない。フロントエンドとバックエンドの両方で排他制御する。

## 5. 処理の流れ

1. 画面で設定と対象を確定し、既存のSD操作と共有する排他状態を取得する。
2. 既存の管理者権限プロセスを利用する。UACキャンセルは無変更で終了する。
3. 管理者側で対象・設定を再検査する。操作計画と実行IDを固定し、古い画面や二重押下からの要求を拒否する。
4. 対象ディスクの全ボリュームの使用状態を確認し、必要なアンマウント・排他処理を行う。取得失敗時は構成を変更しない。
5. 既存構成を削除し、必要なディスク初期化、MBRと単一パーティションの作成を行う。パーティションが残っている場合も、初回版では同じ再作成方式に統一する。
   構成削除後にRAWならMBRで初期化する。MBR初期化済みなら再初期化せず、パーティション作成へ進む。
   ただし、Windowsが開始位置0・カード全容量の単一ボリュームとして公開するメディアでは、構成削除と再作成を行わず、そのボリュームを使う。
6. Windowsの機能で指定ファイルシステムのクイックフォーマットとラベル設定を行う。
7. 新しいボリュームにドライブ文字を割り当てる。元の文字が空いていれば再利用し、無理なら別の空き文字を割り当てる。他ドライブの文字は変更しない。
8. 構成・ファイルシステム・容量・ラベル・マウント状態を再取得して確認する。
9. 簡易テストを選択した場合だけ、小さな一時ファイルを作成し、書込確定後に再オープンして内容を照合、削除する。実行対象の全工程が成功した場合に正常完了とし、テスト確認ログは実行時だけ表示する。
10. ドライブ一覧を更新し、完了後の対象ドライブを選択する。

Windows Storage Management API／Storageモジュールを実装候補とする。PowerShellを使う場合は固定スクリプトと構造化引数で実行し、ラベル等をコマンド文字列へ埋め込まない。
既存のSDドライブ選択欄で選択したSDカードをフォーマットする。
他のSD操作と同時実行せず、選択したSDカードのフォーマットを完了させる。

## 6. 進捗・ログ・終了

- 「開始」直後に最初の工程として「1/5 フォーマット準備中 ○ms」を表示する。簡易テスト選択時は1/6とする。再検査・起動・情報取得中は100ms間隔で経過時間を更新し、最初の後続工程通知で時間を確定する。
- 既存の進捗ポップアップの表示方法を利用し、「事前確認」「パーティション作成」「フォーマット」「動作確認」「完了／失敗」の段階を表示する。
- フォーマットの進捗バーは工程番号／総工程数に連動する。準備を含む総工程数は通常5、簡易テスト選択時6とし、正常完了時に100%とする。処理時間や処理バイト数の割合ではなく、工程の段階を表す。
- 正常完了時はドライブ文字、ファイルシステム、利用可能容量、ラベルを表示する。正常完了まで100％にしない。
- 準備に続く各工程の完了時に「2/5 パーティション作成 14ms」「3/5 フォーマット実行 35ms」「4/5 フォーマット確認 21ms」「5/5 フォーマット完了 502ms」の形式でログを表示する。時間は処理側のStopwatchで実測する。簡易テスト選択時は分母を6に揃え、成功後に「6/6 FAT簡易テスト 550ms」の形式で追加する。数値は例であり、固定値ではない。
- パーティション工程は対象構成の準備、フォーマット工程は実行とドライブ文字の割当、結果工程は構成・形式・容量・ラベルの確認、完了工程は対象カードの最終確認と結果の作成、簡易テスト工程はファイルの書込・読出・削除と対象確認を計測する。起動・通信・FAT詳細判別などは最終行の全体時間に含むため、各工程の時間の合計とは一致しない場合がある。
- 右上と進捗バーは工程開始時に更新し、最終工程の処理中は100%未満を維持する。対象ドライブ・形式・容量・ラベルは完了画面上部に表示する。
- 正常完了時は右上に「5/5 (100%)」、ログの最終行に強調表示で「フォーマット完了 5/5 所要秒数」を表示する。簡易テスト選択時は両方を6/6とする。処理中の説明は終了時に消し、状態を「完了」とする。失敗時にはこれらの完了表示を出さない。
- `panel_text` に `「SDフォーマット」ボタン押下` を一度記録する。処理の詳細と結果はポップアップに表示し、診断ログに実行ID・対象・設定・各段階・Windowsのエラー情報を記録する。
- 実行中はSD読込・書込・FF初期化・ドライブ変更・ドロップ・F5・アップデート・通常終了を禁止する。
- 初期実装では開始後の途中キャンセルは設けない。異常・タイムアウト・通信断では処理の生存状態を確認し、子プロセスが書換えを継続している間は次のSD操作を許可しない。
- エラー時は後続処理を停止し、変更済みの構成は自動で元に戻さない。失敗段階とカードの現在状態、再実行の必要性を表示する。
- 成功・失敗後もログを保持し、対象一覧を再取得する。別カードへ自動で処理を継続しない。

## 7. 既存実装との接続

- `src/components/SdMenu.vue`：メニュー項目、フォーマット要求イベント、実行可否。
- `src/pages/HomeView.vue`：設定・確認画面、共通の操作制限、進捗・結果表示。
- `src-tauri/src/lib.rs`：対象一覧・事前計画・実行用のTauri APIと排他制御。
- `src-tauri/src/sd_worker.rs`：既存の認証済み接続・管理者プロセス・実行中状態の仕組みを拡張。
- `src-tauri/src/sd_format.rs`：計画作成、対象検査、Windows処理、完了結果の検査。
- `src-tauri/src/sd_format.ps1`：Windows Storageモジュールによる構成作成とファイルの読戻し検査。exeへ埋め込み、JSON入力で呼び出す。外部ps1ファイルの配置は不要。
- 既存のFF初期化の動作やCSV範囲は変更しない。フォーマット前にFF初期化を自動実行しない。

## 8. 受入条件

| ケース | 期待結果 |
| --- | --- |
| ファイルシステムなし・ドライブ文字なし | 「?:」として表示し、フォーマットを選択できる |
| 付属CSVによるFF初期化後 | SDデバイスと容量が取得できれば、ファイルシステムに依存せず既存の選択欄からフォーマットできる |
| パーティション・FATが正常なカード | 確認したカードだけを作り直し、選択した形式になる |
| 画像の約474.50MBカード | 合意したFAT16・配置条件で作成し、Windowsと使用機器で認識する |
| CSVなし・入力ファイルなし | フォーマットの可否に影響しない |
| 確認画面のキャンセル／UACキャンセル | カードに変更がない |
| 既存SD操作の共通検査で拒否される対象 | フォーマットでも同じく拒否する |
| 確認後のカード交換 | 元の要求を停止し、別カードを書き換えない |
| 書込禁止・使用中・対応外の設定 | 書換え前に拒否し、理由を表示する |
| SD／SDHC／SDXCの容量区分と境界付近 | 対応する形式を選択し、作成後の形式・容量を確認する |
| 小容量で指定形式を作成できない／SDUC／MBRの容量上限超過 | パーティションを削除する前に拒否し、対象容量と理由を表示する |
| 二重操作・他のSD処理・更新中 | 同時に開始しない |
| 途中失敗・抜去・通信断 | 正常完了とせず、残存処理を管理し、状態と診断情報を表示する |
| 完了確認の失敗 | Windows処理が成功していても正常完了と表示しない |
| 正常完了 | ファイルの作成・読戻し・削除が成功し、再挿入後も利用できる |

自動テストでは対象選別・設定検査・交換検出・操作順序・各段階の異常・UI排他をモックで検証する。
Windowsでの実際の構成作成は使い捨ての仮想ディスクで先に検証し、メディア識別は別に検証する。テストのために本番の対象選別を緩めない。
実機ではUAC、カードリーダーごとの識別、FF初期化後の再検出、書込禁止、再挿入、対象機器での互換性を確認する。

## 9. 実機での確認事項

1. 約512MBクラスを含むFAT、FAT32、exFATの実機での作成・読戻し。自動選択のバイト境界は第2節のとおり。
2. 対象機器が要求するパーティション開始位置・クラスタサイズ・FAT形式。Windows既定の配置でよいか。
3. Windows Storageモジュールによるパーティション再作成に、対象カードリーダーが対応すること。処理エラー時は段階と理由を表示する。
4. FF初期化後の接続中・再挿入後と、未割当SDからフォーマットした後のドライブ文字を実機確認する。

## 10. 根拠

- [FF初期化の既存要件](sd-ff-initialize-requirements.md)：現行CSVの先頭32KiB、物理ディスクへの書込、既存操作制限。
- [Microsoft：Format-Volume](https://learn.microsoft.com/en-us/powershell/module/storage/format-volume)：既存パーティション上のフォーマット、ファイルシステム・ラベル設定。
- [Microsoft：New-Partition](https://learn.microsoft.com/en-us/powershell/module/storage/new-partition)：パーティションの作成とドライブ文字割当。
- [SD Association：容量区分](https://www.sdcard.org/developers/sd-standard-overview/capacity-sd-sdhc-sdxc-sduc/)：カード規格ごとの容量・ファイルシステム。
- [Microsoft：2TBを超えるディスクのサポート](https://learn.microsoft.com/en-us/troubleshoot/windows-server/backup-and-storage/support-for-hard-disks-exceeding-2-tb)：MBRのアドレス範囲と512バイトセクター時の容量上限。
- [Microsoft：format](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/format)：ファイルシステム・クラスタ数等の作成条件。

Windowsでファイルを保存できることと、SD Association仕様への完全な準拠や個別機器との互換性は別の検証項目として扱う。

## 11. 自動検証

- Rust：容量の下限・上限・形式切替境界、非対応セクターサイズ、ラベルの検査。
- Node：確認前・キャンセル時の非実行、CSVなしでの開始、実行中の操作制限、失敗表示、古い進捗の除外。
- Windows処理のモック：RAW／既存構成からの処理順序、選択ディスク限定、交換・書込禁止・システムディスク・形式不一致・ラベル不正の拒否、途中失敗、フォーマット結果不一致、テストファイルの読戻しと削除。
