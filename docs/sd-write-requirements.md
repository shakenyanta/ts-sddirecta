# SD書込ボタンの処理要件

作成日: 2026年10月23日

## 1. 目的と本書の位置付け

画面の「SD書込」ボタンから、対象フォルダー内のファイルをCSVで定義されたSDカードの領域へ書き込めるようにする。

本書は、協議後に承認されたSD書込の要件と実装方法を記載する。管理者権限は画面とは別のSD操作用プロセスで保持し、アプリ終了まで再利用する。実機でのUAC・SDアクセスと性能の確認は、自動テストとビルドの検証とは別に行う。

## 2. 現在の実装

- 「SD書込」ボタンの押下イベントは実装されている。
- 最新のCSV・ファイル・SDを検査し、進捗ポップアップを表示して一括書込・照合を実行する。
- 既存の単発APIに加え、ハンドルとバッファを再利用する一括処理を実装している。
- CSVから作成する領域情報には、ファイル名、アクセスフラグ、開始アドレス、終了アドレスが含まれる。

## 3. 書込対象と領域の定義

### 3.1. 書込先

画面で選択したSDドライブを使用する。開始前にメディアの存在と容量を再確認する。

### 3.2. 対象フォルダーとファイル

現在画面に表示している対象フォルダーを使用する。ファイル照合により表示先が `input` フォルダーへ切り替わっている場合は、その `input` フォルダーを使用する。

SD書込ボタンは「全エリアSD書き込み」の動作とし、`sdloadingDictionary` に登録された一致ファイルを対象とする。ファイル名は拡張子を含めて完全一致で照合し、拡張子だけが異なるファイルは対象に含めない。

アクセスフラグは `E` 以外（`A`・`W`・`R`・`N`・`0` など）をすべて書込対象とする。`E` 行はCSVの終端とし、その行とそれ以降は対象に含めない。ファイルが存在しない領域には書き込まない。

画面のファイル数は `SD書込ファイル数：選択3件 全7件` の形式で表示する。「選択」は `A`・`W`、「全」は `E` 以外（`A`・`W`・`R`・`N`・`0` など）のフラグを持つ一致ファイル数とする。存在しないファイルはどちらにも含めず、`E` 行とそれ以降はCSVの終端として集計対象に含めない。

SD書込ボタンの有効判定、進捗ポップアップの対象件数、書込・照合の対象は「全」の件数に合わせる。「選択」が0件でも「全」が1件以上あれば実行可能とする。

### 3.3. 書込領域

CSVの開始アドレスと終了アドレスを16進数のバイト位置として扱う。終了アドレスは領域に含める。

```text
領域サイズ = 終了アドレス − 開始アドレス ＋ 1
```

ファイルごとの書込は、そのファイルに対応する領域内に収める。別の領域や、書込対象ではない領域には書き込まない。SDカード全体の初期化は、このボタンの処理に含めない。

## 4. ファイルサイズに応じた処理（確定）

ファイルサイズと領域サイズが一致しないことを理由に、書込を拒否したり、そのファイルをスキップしたりしない。書込対象として選別された既存ファイルには、次の規則を適用する。

| 条件 | 書込内容 | `panel_text` への表示 |
| --- | --- | --- |
| ファイルサイズ ＝ 領域サイズ | ファイル全体を書き込む。 | 通常の処理結果を表示する。 |
| ファイルサイズ ＞ 領域サイズ | ファイルの先頭から領域サイズ分を書き込み、超過分は無視する。 | 超過分を無視した旨を注意コメントとして表示する。 |
| 0 ＜ ファイルサイズ ＜ 領域サイズ | ファイル全体を書き込み、領域の残りを `0xFF` で埋める。 | 書込バイト数と `0xFF` による補完バイト数を表示する。 |
| ファイルサイズ ＝ 0バイト | 対象領域全体を `0xFF` で埋める。 | 領域全体を `0xFF` で埋めた旨を表示する。 |
| ファイルが存在しない | その領域には書き込まない。既存データを保持する。 | 対象件数に含めない。 |

0バイトのファイルは、領域全体を `0xFF` で埋めるための有効な入力として扱う。その領域へ何も書き込みたくない場合は、対応するファイルを対象フォルダーから削除する。

「必ず書き込む」とは、サイズの不一致を理由に処理を拒否しないことを意味する。ファイル読取失敗、領域定義の不備、SDカードの障害などがある場合の扱いは、書込前検査と異常時の要件に従う。

### 表示例

以下は、いずれも領域サイズが1,024バイトの場合の例である。

```text
注意: FILE-AA.001 は領域サイズを超えています。ファイル: 1,536バイト、領域: 1,024バイト。末尾512バイトを無視して書き込みます。
FILE-AB.001: ファイル512バイトを書き込み、残り512バイトを0xFFで埋めます。
FILE-AC.001: 0バイトのため、対象領域1,024バイト全体を0xFFで埋めます。
```

これらの事前説明と、実際の成功・失敗を示す処理結果は区別して表示する。

## 5. ボタン押下後の処理

### 5.1. 対象の再確認と書込前検査

CSVと対象フォルダー内のファイルを再確認し、今回の書込対象を確定する。書込対象が0件の場合は、その旨を表示して終了する。

書込開始前に、全対象について次の項目を検査する。

- 対象ファイルが存在し、読み取れること。0バイトは正常とする。
- 開始アドレスと終了アドレスが有効で、開始アドレスが終了アドレス以下であること。
- 書込対象の領域同士が重複していないこと。
- 全対象の終了アドレスがSDカードの容量内に収まること。
- 選択したドライブにメディアが存在し、書込先として利用できること。

不備が1件でも見つかった場合は、SDカードへの書込を開始せず、`panel_text` に原因を表示する。ファイルサイズの超過・不足は不備として扱わず、第4節の規則を適用する。

対象確定後にファイルが消失した場合は、正常な対象外扱いに変更せず、入力の変更として検出して停止する。

### 5.2. 実行内容の確認

書込先ドライブ、容量、対象フォルダー、対象件数、総書込バイト数を表示し、利用者の「書込開始」操作で実行する。総書込バイト数は、切り詰めと `0xFF` 補完を反映した対象領域サイズの合計とする。

### 5.3. 書込と照合

開始アドレスの昇順に、1ファイルずつ書き込む。書込後に同じ領域を読み戻し、期待するデータと照合する。

照合対象は元ファイル全体ではなく、第4節の規則で生成した領域サイズ分のデータとする。ファイルが大きい場合は領域内に収まる先頭部分、小さい場合は末尾の `0xFF` を含むデータ、0バイトの場合は領域全体の `0xFF` を比較する。

効率化のため、SD書込ボタンは既存の単発APIをブロックごとに呼ばず、一括処理を使用する。

| 用途 | 呼出元のRust関数 | 実際にSDへアクセスする関数（`src-tauri/src/windows_api.rs`） |
| --- | --- | --- |
| 一括処理の開始 | `run_sd_write` → `sd_worker::write_batch` → `sd_batch::execute` | `BatchDisk::open` で一括処理用ハンドルを取得 |
| 書込 | `sd_batch::transfer` | `BatchDisk` の `Disk::write` と `Disk::flush` |
| 照合用の読み戻し | `sd_batch::transfer` | `BatchDisk` の `Disk::read` |

`prepare_sd_write` で書込計画を作成する。確認一覧を挟まず、`run_sd_write` が計画を再検査し、`sd_worker::invoke_blocking` を経由して、認証済みの管理者プロセスへ渡す。管理者プロセス内の `sd_worker::serve_requests` が `sd_batch::execute` を実行する。

`sd_batch::expected` で切り詰め・`0xFF` 補完後のデータを生成し、`sd_batch::transfer` で読み戻しデータとバイト単位で比較する。最初の不一致アドレスをエラーとして返す。全対象ファイルを事前に開き、書込・削除共有を許可せず保持する。

一括処理は最大4MiB単位に分割し、約8MiBの整列済みバッファと単一の物理ディスクハンドルを再利用する。領域端のセクターは既存データを読んで対象外の部分を保持する。各ファイルの書込後にフラッシュし、OSキャッシュを経由しない読み戻しで照合する。ファイル本体はプロセス間や画面へ転送せず、進捗と結果のみを通知する。

既存の `sd_write`／`windows_api::sd_write`、`sd_read`／`windows_api::sd_read` は単発操作用として残す。一定値を検査する `sd_verify_fill`／`windows_api::sd_verify_fill` は、ファイル全体の照合には使用しない。

### 5.4. 進捗と操作制限

SD書込ボタン押下時からモーダルの進捗ポップアップを表示する。書込内容の確認一覧は表示しない。淡色背景の角丸パネルに、青い進捗バー、完了件数・進捗率、現在のファイルと処理段階、経過時間／総所要時間、暗色背景のログ欄を配置する。「ログをコピー」と「閉じる」を下部へ配置し、処理中は閉じるボタンとEscで閉じられないようにする。完了・失敗・対象0件・事前検査エラー時も結果を保持し、利用者が閉じる。フォームのサイズは変更せず、ポップアップを画面内の幅・高さまで拡張する（最大650×480px、画面端の余白4px）。見出しと完了件数・進捗率は横並び、時間はボタン行に表示し、ログ欄には残りの高さを割り当てる。小さい画面では余白8px・ログ11px／行高1.2・細いスクロールバーと小さいボタンを使用して表示行数を増やし、必要に応じてログ内をスクロールする。ログは折り返さず、長い行を横スクロールで確認できるようにする。処理状況のファイル名は1行で省略表示し、マウスを重ねると全文を表示する。時間は数値と単位のみとし、完了時はタイトルと重複する状態名を表示しない。準備開始・対象情報の更新・CSV読込・dictionary作成・inputフォルダー・拡張子警告などの読込メッセージは `panel_text` のみに残す。書込先、書込サイズに関する注意、ファイルごとの完了・失敗、全体の結果、未実行ファイルはポップアップのみに残し、両方へ同じログを出力しない。コピー対象は今回のポップアップのログのみとする。ポップアップの総書込サイズ、ファイルサイズ、領域サイズ、補完サイズ、超過サイズは `1,235(0x4d3)バイト` のように、3桁区切りの十進数と小文字の十六進数を併記する（0バイトも `0(0x0)バイト` とする）。`panel_footer` には操作案内を表示する。

#### 表示項目

| 項目 | 表示と意味 |
| --- | --- |
| 現在のファイル | `処理中 3/11: FILE-AB.001` のように、処理順と総対象件数、ファイル名を表示する。 |
| 完了件数 | `完了 2/11件` のように、書込と照合の両方が成功した件数を表示する。処理中のファイルは含めない。 |
| 処理段階 | `準備中`・`書込中`・`照合中`・`完了`・`失敗` を区別する。UAC確認中は `権限確認待ち` とする。 |
| 全体の進捗 | パーセントとプログレスバーを表示する。計算方法は後述する。 |
| 全体の経過時間 | 実行中・終了時とも `1.28秒`、`2.54秒` のように数値と単位のみ表示する。 |
| ファイルごとの所要時間 | 完了ログに `253ms` のように数値と単位のみ表示する。必要に応じて書込・照合の内訳も表示する。 |

例えば3番目のファイルを処理している場合、`処理中 3/11` と `完了 2/11件` を併記し、着手済みの件数と正常完了した件数を区別する。総対象件数は開始時に確定した書込対象ファイル数とし、0バイトのファイルを含み、存在しないファイルとアクセスフラグによる対象外ファイルを含めない。

#### パーセントの計算

ファイルごとにサイズが異なるため、全体のパーセントは件数ではなく、切り詰め・`0xFF` 補完後の処理バイト数に基づいて計算する。書込と照合の両方を進捗に含める。

```text
総処理量 = 全対象の領域サイズ合計 × 2（書込分 ＋ 照合分）
完了処理量 = 書込完了バイト数 ＋ 読み戻して一致を確認したバイト数
全体進捗率 = 完了処理量 ÷ 総処理量 × 100
```

これは処理量の割合であり、残り時間の割合ではない。ファイルから読み込んだだけのデータや、失敗した書込・照合の未完了部分は加算しない。`0xFF` 補完分も書込と照合の処理量に含める。サイズ超過により無視したファイル末尾は含めない。

表示は整数パーセントとし、全対象の書込・照合と終了処理が正常に完了するまでは最大99%とする。正常終了時に100%へ更新する。失敗時はその時点の進捗率を保持し、`失敗` と明示する。対象0件の場合は割合を計算せず、`書込対象なし` と表示する。

照合を行わない仕様に変更する場合は、総処理量を全対象の領域サイズ合計とし、書込完了バイト数のみで計算する。

#### 所要時間の測定

- ファイルごとの所要時間は、そのファイルのデータ準備開始から書込・照合の完了までとする。読取、切り詰め・補完、書込、照合、これらに伴う待ち時間を含める。失敗時は停止までの時間を表示する。
- 全体の所要時間は、事前検査・利用者の開始操作・UAC承認を終え、実際の一括処理を開始した時点から、最後の照合と終了処理の完了までとする。ファイル間の処理時間を含める。失敗時は停止処理の完了までとする。
- 利用者の確認操作やUAC承認待ちの時間は、ファイルごと・全体の所要時間に含めない。
- 時間の計測にはRustの `std::time::Instant` を使用する。システム時計の変更で測定値が変わらないようにする。
- ファイルごとの時間は整数のミリ秒、全体の時間は小数点以下2桁の秒で表示する。例えば `253ms`、`2.54秒` とする。

全体の所要時間はファイル間の処理や終了処理も含むため、ファイルごとの所要時間の合計とは必ずしも一致しない。書込・照合の時間内訳を表示する場合も、準備や待ち時間を含むファイル全体の時間と区別する。

#### 表示例

実行中の表示例:

```text
処理中 3/11: FILE-AB.001
照合中 | 完了 2/11件 | 全体 24% | 経過 1.28秒
```

完了ログの表示例:

```text
2/11 FILE-AA.001 253ms ✓
3/11 FILE-AB.001 187ms ✓
全件完了 11/11 2.54秒
```

失敗時は、例えば `失敗 3/11 FILE-AB.001 187ms: 照合不一致` と表示し、正常完了件数と全体の停止までの所要時間を別途表示する。

#### 更新方法と操作制限

Rust側からフロントエンドへ、今回の実行を識別するID、対象ファイル名、処理順、総件数、完了件数、処理段階、処理バイト数、経過時間を `sd-progress` イベントで通知する。フロントエンドは実行IDが一致する通知のみを表示に反映する。

大きな領域は分割処理の完了時に進捗を通知し、画面の更新は通常100～200ms程度の間隔を目安にまとめる。ファイルの完了・失敗と全体の終了は即時に反映し、短時間で終了したファイルの結果もログへ必ず残す。進捗通知がない間も経過時間を更新する。

処理中は、SD書込ボタンの再押下、ドライブ変更、対象フォルダー変更、ドロップによる切替、F5による再読込を無効にする。

#### 操作制限を示す画面表示

操作できない状態とその理由が見た目でも分かるように、処理中は次の表示を行う。

| 対象 | 処理中の表示と動作 |
| --- | --- |
| SD書込ボタン | グレーアウトして押下不可にする。ラベルを処理段階に合わせて `準備中…`・`権限確認待ち…`・`書込中…`・`照合中…` に変更する。 |
| ドライブ選択 | グレーアウトして選択不可にする。選択中のドライブは確認できる状態で表示する。 |
| 対象フォルダー | 現在のパスは読める状態で表示し、フォルダーを変更する操作部はグレーアウトして無効にする。 |
| ドロップによる切替 | ドラッグ時に `SD処理中のため変更できません` と表示する。ドロップ受付を示す強調表示は出さず、ドロップしても対象フォルダーを変更しない。 |
| F5による再読込 | 押下時に `SD処理中のため再読込できません` と表示し、再読込は実行しない。 |

画面上のステータス表示領域には、処理中である間、次の案内を常時表示する。進捗表示や一時的な操作拒否メッセージで、この案内が失われないようにする。

```text
SD処理中：ドライブ・対象フォルダーの変更と再読込はできません
```

F5やドロップの拒否メッセージはステータス表示領域内の一時メッセージとして表示し、繰り返し操作するたびに `panel_text` のログへ追加しない。色の変化だけに頼らず、ボタンのラベルと案内文でも処理中であることを示す。

操作制限は、開始操作を受け付けた時点から、事前検査・権限確認待ちを含めて適用する。正常完了、失敗、対象0件、事前検査エラー、UACキャンセルのいずれの場合も、実行中のSD処理と停止処理が終了してから制限を解除する。解除時はボタンのラベルを `SD書込` に戻し、処理中の案内を消して結果を表示する。各操作の有効・無効は、SDの有無や対象ファイルの有無など、その時点の通常の条件で再判定する。

### 5.5. 完了と異常時の動作

全対象の書込と照合が成功した場合のみ、全体の正常完了を表示する。

書込失敗、照合不一致、SDカードの取り外しなどが発生した場合は、後続処理を停止する。ポップアップには、完了済みのファイル、失敗したファイルと原因、未実行のファイルを表示する。失敗したファイルは、一部だけ書き込まれている可能性があることも表示する。

途中まで書き込んだデータは自動的には元に戻さない。UAC確認をキャンセルした場合は書込を開始せず、その旨を表示する。

## 6. 権限と実装上の留意点

画面は通常権限のまま動作させる。初回の書込でUAC承認を受け、SD操作用の管理者プロセスを起動する。プロセス自身の `TokenElevation` と通信準備を確認した時点で緑ランプにする。

管理者プロセスは書込完了後もアプリ終了まで待機して再利用する。利用可能な間は、次の書込でUACを再表示しない。待機中は緑ランプでもドロップ可能とし、実行中だけ対象変更を禁止する。アプリ終了時に接続を閉じることで管理者プロセスも終了する。実行中の終了操作は受け付けず、処理の完了・停止を待つ。

通常終了時は、接続を閉じた後に `Session::close_and_wait` が `WaitForSingleObject` でSD操作プロセスの終了通知を待ち合わせる。終了を確認してから画面を閉じる。待機は別スレッドで行い、画面のイベント処理を止めない。待機中は「終了待ち…」「SD操作プロセスの終了を確認しています」と表示し、新たなSD操作や対象変更を禁止する。終了確認に失敗した場合は、画面を閉じずに原因と終了操作の再試行案内を表示する。

ランプは未取得・終了済み・UACキャンセル後が灰色、権限確認中が黄色点滅、利用可能が緑色、取得・通信失敗が赤色とする。通信切断時は管理者プロセスの終了を確認するまで操作制限を維持し、次の書込で再度UAC確認を行う。

SD容量・ディスク番号を開始前に再確認する。SDボリュームは一括処理中にロックし、ロックできなければ書き込まない。複数のドライブ文字を持つ同一ディスクは受け付けない。書込元ファイルは書込先SD以外に置く。

切り詰め、`0xFF` 補完、実書込、照合のすべてについて、CSVで指定された領域外を変更しないことを保証する。特に、既存の低レベル書込処理のセクター境界の扱いを確認する。

## 7. サイズ処理の受入条件（確定事項の検証）

領域サイズが1,024バイトの場合、次を満たすこと。

| 入力 | 期待結果 |
| --- | --- |
| 1,024バイトのファイル | 元データ1,024バイトが書き込まれる。 |
| 1,536バイトのファイル | 先頭1,024バイトが書き込まれ、末尾512バイトは無視される。`panel_text` に注意コメントが表示される。 |
| 512バイトのファイル | 元データ512バイトと、続く512バイトの `0xFF` が書き込まれる。 |
| 0バイトのファイル | 領域全体の1,024バイトが `0xFF` になる。 |
| 対応するファイルがない | その領域の既存データが保持される。 |

いずれの場合も、対象領域の前後のデータが変更されないことを確認する。

## 8. 承認済みの実装方針と実機確認

- SD書込ボタンは全エリアSD書込として、`E` 以外の全フラグの一致ファイルを書込対象とする。
- 確認一覧を表示せず、進捗と結果を確認できるポップアップを設ける。
- 全対象に対して書込後の読み戻し照合を行う。
- 管理者プロセスをアプリ終了まで再利用し、利用可能な間はUAC確認を繰り返さない。

自動テストでは模擬ディスクと模擬APIを使い、実SDカードへアクセスしない。実機でのUAC承認・キャンセル、管理者プロセス再利用、ドロップ、SD取り外し、実データの書込・読み戻し、カードごとの実測速度は別途確認する。
