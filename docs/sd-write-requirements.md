# SD書込ボタンの処理要件

作成日: 2026年10月23日

## 1. 目的と本書の位置付け

画面の「SD書込」ボタンから、対象フォルダー内のファイルをCSVで定義されたSDカードの領域へ書き込めるようにする。

本書は、協議後に承認されたSD書込の要件と実装方法を記載する。管理者権限は画面とは別のSD操作用プロセスで保持し、アプリ終了まで再利用する。実機でのUAC・SDアクセスと性能の確認は、自動テストとビルドの検証とは別に行う。

## 2. 現在の実装

- 「SD書込」ボタンの押下イベントは実装されている。
- 最新のCSV・ファイル・SDを検査し、進捗ポップアップを表示して一括書込・照合を実行する。
- 既存の単発APIに加え、ハンドルとバッファを再利用する一括処理を実装している。
- CSVから作成する領域情報には、ファイル名、アクセスフラグ、開始アドレス、終了アドレスが含まれる。

## 3. 書込対象と領域の定義

### 3.1. 書込先

画面で選択したSDドライブを使用する。開始前にメディアの存在と容量を再確認する。

### 3.2. 対象フォルダーとファイル

現在画面に表示している対象フォルダーを使用する。ファイル照合により表示先が `input` フォルダーへ切り替わっている場合は、その `input` フォルダーを使用する。

SD書込ボタンは「全エリアSD書き込み」の動作とし、`sdloadingDictionary` に登録された一致ファイルを対象とする。ファイル名は拡張子を含めて完全一致で照合し、拡張子だけが異なるファイルは対象に含めない。

アクセスフラグは `E` 以外（`A`・`W`・`R`・`N`・`0` など）をすべて書込対象とする。`E` 行はCSVの終端とし、その行とそれ以降は対象に含めない。ファイルが存在しない領域には書き込まない。

画面のファイル数は `SD書込ファイル数：全7件` の形式で表示し、「全7件」の部分を太字にする。「全」は `E` 以外（`A`・`W`・`R`・`N`・`0` など）のフラグを持つ一致ファイル数とする。存在しないファイルは含めず、`E` 行とそれ以降はCSVの終端として集計対象に含めない。

SD書込ボタンの有効判定、進捗ポップアップの対象件数、書込・照合の対象は「全」の件数に合わせる。`A`・`W` の一致ファイルが0件でも「全」が1件以上あれば実行可能とする。

### 3.3. 書込領域

CSVの開始アドレスと終了アドレスを16進数のバイト位置として扱う。終了アドレスは領域に含める。

```text
領域サイズ = 終了アドレス − 開始アドレス ＋ 1
```

ファイルごとの書込は、そのファイルに対応する領域内に収める。別の領域や、書込対象ではない領域には書き込まない。SDカード全体の初期化は、このボタンの処理に含めない。

## 4. ファイルサイズに応じた処理（確定）

ファイルサイズと領域サイズが一致しないことを理由に、書込を拒否したり、そのファイルをスキップしたりしない。書込対象として選別された既存ファイルには、次の規則を適用する。

| 条件 | 書込内容 | ポップアップへの表示 |
| --- | --- | --- |
| ファイルサイズ ＝ 領域サイズ | ファイル全体を書き込む。 | 通常の処理結果を表示する。 |
| ファイルサイズ ＞ 領域サイズ | ファイルの先頭から領域サイズ分を書き込み、超過分は無視する。 | `ファイル名:[警告]容量オーバー` と表示する。 |
| 0 ＜ ファイルサイズ ＜ 領域サイズ | ファイル全体を書き込み、領域の残りを `0xFF` で埋める。 | `ファイル名:[注意]容量不足 → FF埋め` と表示する。 |
| ファイルサイズ ＝ 0バイト | 対象領域全体を `0xFF` で埋める。 | `ファイル名:[注意]容量不足 → FF埋め` と表示する。 |
| ファイルが存在しない | その領域には書き込まない。既存データを保持する。 | 対象件数に含めない。 |

0バイトのファイルは、領域全体を `0xFF` で埋めるための有効な入力として扱う。その領域へ何も書き込みたくない場合は、対応するファイルを対象フォルダーから削除する。

「必ず書き込む」とは、サイズの不一致を理由に処理を拒否しないことを意味する。ファイル読取失敗、領域定義の不備、SDカードの障害などがある場合の扱いは、書込前検査と異常時の要件に従う。

### 表示例

以下は、いずれも領域サイズが1,024バイトの場合の例である。

```text
FILE-AA.001:[警告]容量オーバー
FILE-AB.001:[注意]容量不足 → FF埋め
FILE-AC.001:[注意]容量不足 → FF埋め
```

これらの事前説明と、実際の成功・失敗を示す処理結果は区別して表示する。

## 5. ボタン押下後の処理

### 5.1. 対象の再確認と書込前検査

CSVと対象フォルダー内のファイルを再確認し、今回の書込対象を確定する。書込対象が0件の場合は、その旨を表示して終了する。

書込開始前に、全対象について次の項目を検査する。

- 対象ファイルが存在し、読み取れること。0バイトは正常とする。
- 開始アドレスと終了アドレスが有効で、開始アドレスが終了アドレス以下であること。
- 書込対象の領域同士が重複していないこと。
- 全対象の終了アドレスがSDカードの容量内に収まること。
- 選択したドライブにメディアが存在し、書込先として利用できること。

不備が1件でも見つかった場合は、SDカードへの書込を開始せず、`panel_text` に原因を表示する。ファイルサイズの超過・不足は不備として扱わず、第4節の規則を適用する。

対象確定後にファイルが消失した場合は、正常な対象外扱いに変更せず、入力の変更として検出して停止する。

### 5.2. 実行内容の確認

書込先ドライブ、容量、対象フォルダー、対象件数、総書込バイト数を表示し、利用者の「書込開始」操作で実行する。総書込バイト数は、切り詰めと `0xFF` 補完を反映した対象領域サイズの合計とする。

### 5.3. 書込と照合

開始アドレスの昇順に、1ファイルずつ書き込む。書込後に同じ領域を読み戻し、期待するデータと照合する。

照合対象は元ファイル全体ではなく、第4節の規則で生成した領域サイズ分のデータとする。ファイルが大きい場合は領域内に収まる先頭部分、小さい場合は末尾の `0xFF` を含むデータ、0バイトの場合は領域全体の `0xFF` を比較する。

効率化のため、SD書込ボタンは既存の単発APIをブロックごとに呼ばず、一括処理を使用する。

| 用途 | 呼出元のRust関数 | 実際にSDへアクセスする関数（`src-tauri/src/windows_api.rs`） |
| --- | --- | --- |
| 一括処理の開始 | `run_sd_write` → `sd_worker::write_batch` → `sd_batch::execute` | `BatchDisk::open` で一括処理用ハンドルを取得 |
| 書込 | `sd_batch::transfer_phases` | `BatchDisk` の `Disk::write` と `Disk::flush` |
| 照合用の読み戻し | `sd_batch::transfer_phases` | `BatchDisk` の `Disk::read` |

`prepare_sd_write` で書込計画を作成する。確認一覧を挟まず、`run_sd_write` が計画を再検査し、`sd_worker::invoke_blocking` を経由して、認証済みの管理者プロセスへ渡す。管理者プロセス内の `sd_worker::serve_requests` が `sd_batch::execute` を実行する。

`sd_batch::expected` で切り詰め・`0xFF` 補完後のデータを生成し、`sd_batch::transfer_phases` で読み戻しデータとバイト単位で比較する。最初の不一致アドレスをエラーとして返す。全対象ファイルを事前に開き、書込・削除共有を許可せず保持する。

各ファイルの書込・直後照合がすべて終了した後、`sd_batch::run_entries` が全対象を再読込して最終照合する。この段階では追加の書込は行わない。正常完了通知は全対象の最終照合とSDハンドル解放の後に限る。

一括処理は最大4MiB単位に分割し、書込・SD読込・期待値用の独立した3つの整列済みバッファ（合計約12MiB）と単一の物理ディスクハンドルを再利用する。領域端のセクターはSD読込用バッファへ既存データを読み、書込用バッファへコピーして対象外の部分を保持する。各ファイルの書込後にフラッシュし、OSキャッシュを経由しない読み戻しで照合する。照合前に読込先を期待値のビット反転値で埋め、未更新部分が残留データで一致することを防ぐ。ファイル本体はプロセス間や画面へ転送せず、進捗と結果のみを通知する。

既存の `sd_write`／`windows_api::sd_write`、`sd_read`／`windows_api::sd_read` は単発操作用として残す。一定値を検査する `sd_verify_fill`／`windows_api::sd_verify_fill` は、ファイル全体の照合には使用しない。

### 5.4. 進捗と操作制限

「SD書込」ボタン押下時からモーダルの進捗ポップアップを表示する。書込内容の確認一覧は表示しない。淡色背景の角丸パネルに、青い進捗バー、完了件数・進捗率、現在のファイルと処理段階、経過時間／総所要時間、暗色背景のログ欄を配置する。「ログをコピー」と「閉じる」を下部へ配置し、処理中は閉じるボタンとEscで閉じられないようにする。完了・失敗・対象0件・事前検査エラー時も結果を保持し、利用者が閉じる。フォームのサイズは変更せず、ポップアップを画面内の幅・高さまで拡張する（最大650×480px、画面端の余白4px）。見出しと完了件数・進捗率は横並び、時間はボタン行に表示し、ログ欄には残りの高さを割り当てる。小さい画面では余白8px・ログ11px／行高1.2・細いスクロールバーと小さいボタンを使用して表示行数を増やし、必要に応じてログ内をスクロールする。ログは折り返さず、長い行を横スクロールで確認できるようにする。処理状況のファイル名は1行で省略表示し、マウスを重ねると全文を表示する。時間は数値と単位のみとし、完了時はタイトルと重複する状態名を表示しない。起動時・ドロップ時・F5のCSV読込・dictionary作成・inputフォルダー・拡張子警告は `panel_text` のみに残す。SD書込押下時は既存ログの直下に `「SD書込」ボタン押下` を追記し、同じ初期読込ログを再出力しない。最新CSV・ファイルの検査はバックエンドで行い、準備開始のメッセージはポップアップに表示する。書込先、書込サイズに関する注意、ファイルごとの完了・失敗、全体の結果、未実行ファイルはポップアップのみに残し、両方へ同じログを出力しない。コピー対象は今回のポップアップのログのみとする。サイズ不一致のログは第4節の簡潔な表示とし、詳細なバイト数は表示しない。ポップアップの総書込サイズは `1,235(0x4d3)バイト` のように、3桁区切りの十進数と小文字の十六進数を併記する（0バイトも `0(0x0)バイト` とする）。`panel_footer` には操作案内を表示する。

#### 表示項目

| 項目 | 表示と意味 |
| --- | --- |
| 現在のファイル | `処理中 3/11: FILE-AB.001` のように、処理順と総対象件数、ファイル名を表示する。 |
| 完了件数 | `完了 2/11件` のように、全書込後の最終照合が成功した件数を表示する。処理中のファイルは含めない。 |
| 処理段階 | `準備中`・`書込中`・`照合中`・`最終照合中`・`完了`・`失敗`・`最終照合失敗` を区別する。UAC確認中は `権限確認待ち` とする。 |
| 全体の進捗 | パーセントとプログレスバーを表示する。計算方法は後述する。 |
| 全体の経過時間 | 実行中・終了時とも `1.28秒`、`2.54秒` のように数値と単位のみ表示する。 |
| ファイルごとの所要時間 | 完了ログに `253ms` のように数値と単位のみ表示する。必要に応じて書込・照合の内訳も表示する。 |

例えば3番目のファイルを処理している場合、`処理中 3/11` と `完了 2/11件` を併記し、着手済みの件数と正常完了した件数を区別する。総対象件数は開始時に確定した書込対象ファイル数とし、0バイトのファイルを含み、存在しないファイルとアクセスフラグによる対象外ファイルを含めない。

#### パーセントの計算

ファイルごとにサイズが異なるため、全体のパーセントは件数ではなく、切り詰め・`0xFF` 補完後の処理バイト数に基づいて計算する。書込・直後照合・最終照合を進捗に含める。

```text
総処理量 = 全対象の領域サイズ合計 × 3（書込分 ＋ 直後照合分 ＋ 最終照合分）
完了処理量 = 書込完了バイト数 ＋ 直後照合で一致したバイト数 ＋ 最終照合で一致したバイト数
全体進捗率 = 完了処理量 ÷ 総処理量 × 100
```

これは処理量の割合であり、残り時間の割合ではない。ファイルから読み込んだだけのデータや、失敗した書込・照合の未完了部分は加算しない。`0xFF` 補完分も書込と照合の処理量に含める。サイズ超過により無視したファイル末尾は含めない。

表示は整数パーセントとし、全対象の書込・照合と終了処理が正常に完了するまでは最大99%とする。正常終了時に100%へ更新する。失敗時はその時点の進捗率を保持し、`失敗` と明示する。対象0件の場合は割合を計算せず、`書込対象なし` と表示する。

照合を行わない仕様に変更する場合は、総処理量を全対象の領域サイズ合計とし、書込完了バイト数のみで計算する。

#### 所要時間の測定

- ファイルごとの所要時間は、そのファイルのデータ準備開始から書込・照合の完了までとする。読取、切り詰め・補完、書込、照合、これらに伴う待ち時間を含める。失敗時は停止までの時間を表示する。
- 画面側では「SD書込」ボタン押下時からの経過時間を内部計測するが、ポップアップ左下には表示しない。正常完了ログには、管理者プロセスで一括処理を開始した時点から測定したRustの処理時間を表示する。
- ファイルごとの時間は当該ファイルの処理のみとし、最終照合時間は別の完了ログに表示する。
- 時間の計測にはRustの `std::time::Instant` と画面側の `performance.now()` を使用する。システム時計の変更で測定値が変わらないようにする。
- ファイルごとの時間は整数のミリ秒、全体の時間は小数点以下2桁の秒で表示する。例えば `253ms`、`2.54秒` とする。

全体の所要時間はファイル間の処理や終了処理も含むため、ファイルごとの所要時間の合計とは必ずしも一致しない。書込・照合の時間内訳を表示する場合も、準備や待ち時間を含むファイル全体の時間と区別する。

#### 表示例

実行中の表示例:

```text
処理中 3/11: FILE-AB.001
照合中 | 完了 2/11件 | 全体 24% | 経過 1.28秒
```

完了ログの表示例:

```text
2/11 FILE-AA.001 253ms ✓
3/11 FILE-AB.001 187ms ✓
全件完了 11/11 2.54秒
```

失敗時は、例えば `失敗 3/11 FILE-AB.001 187ms: 照合不一致` と表示し、正常完了件数と全体の停止までの所要時間を別途表示する。

#### 更新方法と操作制限

Rust側からフロントエンドへ、今回の実行を識別するID、対象ファイル名、処理順、総件数、完了件数、処理段階、処理バイト数、経過時間を `sd-progress` イベントで通知する。フロントエンドは実行IDが一致する通知のみを表示に反映する。

大きな領域は分割処理の完了時に進捗を通知し、画面の更新は通常100～200ms程度の間隔を目安にまとめる。ファイルの完了・失敗と全体の終了は即時に反映し、短時間で終了したファイルの結果もログへ必ず残す。進捗通知がない間も経過時間を更新する。

処理中は、SD書込ボタンの再押下、ドライブ変更、対象フォルダー変更、ドロップによる切替、F5による再読込を無効にする。

#### 操作制限を示す画面表示

操作できない状態とその理由が見た目でも分かるように、処理中は次の表示を行う。

| 対象 | 処理中の表示と動作 |
| --- | --- |
| SD書込ボタン | グレーアウトして押下不可にする。ラベルを処理段階に合わせて `準備中…`・`権限確認待ち…`・`書込中…`・`照合中…` に変更する。 |
| ドライブ選択 | グレーアウトして選択不可にする。選択中のドライブは確認できる状態で表示する。 |
| 対象フォルダー | 現在のパスは読める状態で表示し、フォルダーを変更する操作部はグレーアウトして無効にする。 |
| ドロップによる切替 | ドラッグ時に `SD処理中のため変更できません` と表示する。ドロップ受付を示す強調表示は出さず、ドロップしても対象フォルダーを変更しない。 |
| F5による再読込 | 押下時に `SD処理中のため再読込できません` と表示し、再読込は実行しない。 |

画面上のステータス表示領域には、処理中である間、次の案内を常時表示する。進捗表示や一時的な操作拒否メッセージで、この案内が失われないようにする。

```text
SD処理中：ドライブ・対象フォルダーの変更と再読込はできません
```

F5やドロップの拒否メッセージはステータス表示領域内の一時メッセージとして表示し、繰り返し操作するたびに `panel_text` のログへ追加しない。色の変化だけに頼らず、ボタンのラベルと案内文でも処理中であることを示す。

操作制限は、開始操作を受け付けた時点から、事前検査・権限確認待ちを含めて適用する。正常完了、失敗、対象0件、事前検査エラー、UACキャンセルのいずれの場合も、実行中のSD処理と停止処理が終了してから制限を解除する。解除時はボタンのラベルを `SD書込` に戻し、処理中の案内を消して結果を表示する。各操作の有効・無効は、SDの有無や対象ファイルの有無など、その時点の通常の条件で再判定する。

### 5.5. 完了と異常時の動作

全対象の書込と照合が成功した場合のみ、全体の正常完了を表示する。

書込失敗、照合不一致、SDカードの取り外しなどが発生した場合は、後続処理を停止する。ポップアップには、完了済みのファイル、失敗したファイルと原因、未実行のファイルを表示する。失敗したファイルは、一部だけ書き込まれている可能性があることも表示する。

途中まで書き込んだデータは自動的には元に戻さない。UAC確認をキャンセルした場合は書込を開始せず、その旨を表示する。

## 6. 権限と実装上の留意点

画面は通常権限のまま動作させる。初回の書込でUAC承認を受け、SD操作用の管理者プロセスを起動する。プロセス自身の `TokenElevation` と通信準備を確認した時点で緑ランプにする。

管理者プロセスは書込完了後もアプリ終了まで待機して再利用する。利用可能な間は、次の書込でUACを再表示しない。待機中は緑ランプでもドロップ可能とし、実行中だけ対象変更を禁止する。アプリ終了時に接続を閉じることで管理者プロセスも終了する。実行中の終了操作は受け付けず、処理の完了・停止を待つ。

通常終了時は、接続を閉じた後に `Session::close_and_wait` が `WaitForSingleObject` でSD操作プロセスの終了通知を待ち合わせる。終了を確認してから画面を閉じる。待機は別スレッドで行い、画面のイベント処理を止めない。待機中は「終了待ち…」「SD操作プロセスの終了を確認しています」と表示し、新たなSD操作や対象変更を禁止する。終了確認に失敗した場合は、画面を閉じずに原因と終了操作の再試行案内を表示する。

ランプは未取得・終了済み・UACキャンセル後が灰色、権限確認中が黄色点滅、利用可能が緑色、取得・通信失敗が赤色とする。通信切断時は管理者プロセスの終了を確認するまで操作制限を維持し、次の書込で再度UAC確認を行う。

SD容量・ディスク番号を開始前に再確認する。SDボリュームは一括処理中にロックし、ロック成功後、同じボリュームハンドルで `FSCTL_DISMOUNT_VOLUME` を実行する。ロックまたはマウント解除に失敗した場合は書き込まない。ロックは物理ディスクハンドルを閉じるまで保持し、終了・エラー時ともハンドル破棄で解放する。読込専用の一括処理はロック・マウント解除を行わない。複数のドライブ文字を持つ同一ディスクは受け付けない。書込元ファイルは書込先SD以外に置く。

切り詰め、`0xFF` 補完、実書込、照合のすべてについて、CSVで指定された領域外を変更しないことを保証する。特に、既存の低レベル書込処理のセクター境界の扱いを確認する。

## 7. サイズ処理の受入条件（確定事項の検証）

領域サイズが1,024バイトの場合、次を満たすこと。

| 入力 | 期待結果 |
| --- | --- |
| 1,024バイトのファイル | 元データ1,024バイトが書き込まれる。 |
| 1,536バイトのファイル | 先頭1,024バイトが書き込まれ、末尾512バイトは無視される。ポップアップに `ファイル名:[警告]容量オーバー` が表示される。 |

## 9. デバイス待機表示と診断ログ

FF初期化後の再実行を調べるため、`volume snapshot`には既存ハンドルへの`GetVolumeInformationByHandleW`が返すファイルシステム名／フラグ、または取得不能時のWindowsエラー番号を追加する。ドライブを開き直したり読み書き位置を変更したりしない。マウント解除後の取得不能は想定され、RAW状態や故障を意味するとは限らない。

既存の読戻しが物理位置0を含み、先頭512バイトを正常に取得した場合だけ、`boot sector observation`として全FF／全ゼロ・55AA署名・FAT BPBの概況を記録する。診断目的の追加SD読込は行わず、データそのものは記録しない。BPBの概況はファイルシステムの完全性検査ではない。FF初期化では計画と正常完了を明示し、先頭セクターが対象かを残す。完了記録だけで実際の先頭領域を消去したと断定せず、読戻しの観測と照合する。

失敗後の非同期Windows収集では、遅くなる可能性があるドライバー情報の前にStorageのパーティションと関連ボリュームを取得する。観測時刻・パーティション範囲・ドライブ文字・ファイルシステム名／種別・容量／状態を記録する。取得は最大4パーティション・各4ボリュームに制限し、関連付けなし・取得失敗と、明示的なRAW応答を区別する。これらはハンドル解放後の観測であり、直後に別の操作を実行した場合はその影響を含む可能性がある。

SD書込・読込・FF初期化・フォーマットの実行失敗時は、処理内のハンドル解放後にWindows側の証拠を非同期収集する。元の失敗結果は即時に返し、再試行・リセット・修復や書込方式の変更は行わない。正常終了時・定期監視では収集しない。

`windows_failure_evidence`区間は元の`run_id`を引き継ぎ、失敗時刻・対象ドライブ／ディスク番号・期待容量・元エラーと、実行exeのバージョン／SHA-256を記録する。失敗90秒前から3秒後までのSystemのストレージ関連警告・エラーとStorageVolumeのイベントを検索し、時刻・イベントID・レコードID・メッセージ・生のプロパティ値を残す。検索は各チャンネル最大200件、出力は各24件。検索時刻はWindows PowerShellのローカル時刻に変換し、ログ上の期間はUTCで明示する。

デバイス情報は失敗後に観測したWMIディスク情報と最大4段のPnP親デバイスのサービス名・ドライバー提供元／バージョン／日付／INFを記録する。WMI容量と実容量が異なる場合も結果を残すが、同じディスク番号・同容量だけで同じ媒体／リーダーと断定しない。期間内のイベントには別ディスクの記録が含まれ得るため、イベントのディスク番号・PDO・時刻等と照合し、原因確定と扱わない。

Windowsのイベント反映を待つ3秒の後に、収集用PowerShellを最大15秒実行する。収集は同時に1件まで、ログ追記は最大96KiBとし、権限不足・イベントなし・タイムアウト・切詰め・収集省略を区別する。匿名一時ファイルは収集終了時に破棄する。アプリを終了すると収集が完了しない場合があるため、失敗後はアプリを開いたまま約20秒待ってから「診断ログを開く」で確認する。WindowsイベントやPnP情報だけでは拒否元を特定できない場合には、別途Process Monitor等による操作時点のトレースが必要。

失敗画面には元のエラーと取得できた診断内容、主エラー番号に応じた原因候補・対処案を表示し、診断ログを直接開けるようにする。診断取得時のエラー番号を主エラーと混同せず、マウント状態等の取得失敗を「未マウント」「書込禁止」と断定しない。原因候補・対処案はログコピーにも含め、次の操作開始時に前回の表示を消去する。

フォーマット前・パーティション作成後・フォーマット後・完了時と異常時に、Storageが返すディスク番号／パス・接続方式・セクターサイズ・読取専用／オフライン／稼働状態・パーティション範囲・ドライブ文字・ファイルシステムを記録する。SD一括書込では既存ハンドルからロック前後・先頭セクター書込後・書込失敗時のパーティション構成とマウント状態・書込可否を取得し、ハンドルの開閉、失敗時の数値Windowsエラー・転送バイト数・アラインメントも残す。診断取得は読み取り専用とし、ディスク位置・マウント・ロック・キャッシュを変更しない。診断取得失敗で元の処理結果を上書きしない。USB抜き差しや接続先変更前後の比較に使用し、ドライバー内部の状態を断定しない。

準備時・書込時のWindows呼出しを実行IDと処理IDで追跡する。約250ミリ秒間隔の独立した監視処理から、現在の処理名とその経過時間を画面へ通知する。5秒以上継続した処理は応答待ちとして表示し、警告ログを出す。監視だけでSD操作を中断したり操作制限を解除したりしない。

ログは日本時間（+09:00）とUnixミリ秒を併記し、PID・スレッドID・実行ID・処理IDを記録する。各実行区間の終了時にSUMMARYとして総時間と準備・書込・直後照合読込・最終照合読込・flush等の累積時間を出す。ドライブ定期確認は状態／エラー内容の変化と長時間待機を中心に記録し、同じ結果やIPC応答待ちの反復記録を省く。

6. 同条件を再度試し、Eドライブでも確認する。失敗時はその場でログを保存し、拒否が解除APIで起きたか、解除成功後のWriteFileで起きたかを切り分ける。後者ならマウント解除だけでは解決していないため、ドライバー・ボリュームと物理ディスクの対応を追加調査する。

既存版との比較ログは保存済みの失敗ログを使用できる。新しい検証でもカード全体の変更やフォーマットを伴うため、業務用データの入ったカードは使わない。読込専用・RAW状態のカード・FF初期化についても対応機器で実機確認が必要。
