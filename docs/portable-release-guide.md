# ポータブル版のリリース手順

次回以降のリリースで、上から順に進めるための手順書です。
ここでは、公開済みの `0.1.0` から **`0.1.1` を公開する例**で説明します。
実際に公開するバージョンに読み替えてください。

## 全体の流れ

1. バージョンを上げる。
2. コマンドで配布ファイルを作成・署名する。
3. 新しいexeの起動を確認する。
4. GitHubで新しいリリースを作り、3ファイルを添付して公開する。
5. 旧バージョンから更新できることを確認し、利用者へ案内する。

## 1. 作業前に用意するもの

- このプロジェクトをビルドできるWindowsの開発環境。
- これまで使ってきた署名用の秘密鍵と公開鍵。
- 鍵を暗号化した場合は、そのパスワード。
- GitHubの `shakenyanta/ts-sddirecta-releases` にリリースを作成できるアカウント。
- 更新テスト用に残した、旧バージョンのexe。

鍵の標準の保存先は、PowerShellで次の場所です。

```text
$env:USERPROFILE\.tauri\ts-sddirecta.key
$env:USERPROFILE\.tauri\ts-sddirecta.key.pub
```

次のコマンドで保存先フォルダーを開けます。

```powershell
explorer.exe "$env:USERPROFILE\.tauri"
```

**リリースのたびに鍵を作り直す必要はありません。同じ鍵を使い続けます。**
秘密鍵とパスワードは安全な場所にバックアップし、GitHubや配布ファイルには含めないでください。
アプリに組み込むのは公開鍵 `src-tauri/update-public-key.txt` だけです。

## 2. バージョンと変更内容を更新する

次の3か所を、すべて同じバージョンに変更します。

| ファイル | 変更する項目 | 今回の例 |
| --- | --- | --- |
| `package.json` | 先頭付近の `"version"` | `"0.1.1"` |
| `src-tauri/Cargo.toml` | `[package]` 内の `version` | `"0.1.1"` |
| `src-tauri/tauri.conf.json` | 先頭付近の `"version"` | `"0.1.1"` |

依存ライブラリのバージョンは変更しません。
ここで指定する値には `v` を付けず、GitHubのタグには `v` を付けます。

**公開済みの番号は使い回さず、前回より大きい番号にしてください。**
アプリは、公開版が自分より新しい場合だけ更新を案内します。

`CHANGELOG.md` に、今回の変更内容が日本語で記録されていることも確認します。
未コミットの変更は「未リリース」欄に記録します。この手順のためだけにコミットする必要はありません。

## 3. 配布ファイルを作成する

PowerShellを開き、プロジェクトのフォルダーへ移動します。

```powershell
Set-Location 'C:\Users\SYSTEM-PC7\source\repos\electron3\ts-sddirecta'
```

変更内容に応じたテストを実施してから、次のコマンドを実行します。
`-Notes` の文は、利用者に表示する今回の変更内容へ書き換えてください。

```powershell
npm.cmd run release:prepare -- -Notes "SD書込の表示を改善しました。"
```

このコマンドで、バージョンと公開鍵の一致確認、exeのビルド、更新情報の生成、署名を行います。
鍵のパスワードを求められた場合は、PowerShell上で入力します。
処理が終わるまで待ち、最後に **「配布ファイルの作成が完了しました」** と表示されることを確認してください。
途中にビルド完了の表示があっても、署名まで完了している必要があります。

秘密鍵を標準以外の場所に保存している場合は、次のように指定できます。
対応する公開鍵も、秘密鍵のパスに `.pub` を付けた場所に必要です。

```powershell
npm.cmd run release:prepare -- -PrivateKeyPath 'D:\署名鍵\ts-sddirecta.key' -Notes "今回の変更内容"
```

今回の例では、次のフォルダーに3ファイルが作成されます。

```text
dist-update\v0.1.1\
  ts-sddirecta.exe
  latest.json
  latest.json.sig
```

| ファイル | 用途 |
| --- | --- |
| `ts-sddirecta.exe` | 利用者が起動するアプリ本体 |
| `latest.json` | バージョン、exeのダウンロード先・サイズ・ハッシュ、変更内容 |
| `latest.json.sig` | 更新情報が正しいことを確認するための署名 |

**必ず同じ実行で作成した3ファイルをまとめて使用し、名前を変更しないでください。**
生成後にexeやJSONを書き換えると、署名やハッシュが一致しなくなります。
修正が必要な場合は、コマンドで3ファイルを作り直します。

## 4. 公開前に起動を確認する

1. 旧バージョンのexeを、更新テスト用の別フォルダーに残します。
2. 新しい `dist-update\v0.1.1\ts-sddirecta.exe` を起動します。
3. メニューの「バージョン情報」で `0.1.1` と表示されることを確認します。
4. 今回変更した機能が動くことを確認し、アプリを終了します。

exeの起動だけでは、GitHub経由の更新・再起動まで確認したことにはなりません。
実際の更新は、手順6で公開後に確認します。

## 5. GitHubで新しいリリースを公開する

### 5-1. 作成画面を開く

[配布リポジトリのReleases](https://github.com/shakenyanta/ts-sddirecta-releases/releases) を開き、
**「Draft a new release」** を押します。
新規作成画面は、[このリンク](https://github.com/shakenyanta/ts-sddirecta-releases/releases/new) からも開けます。

### 5-2. タグ・タイトル・説明を入力する

| 画面の英語表記 | 入力・選択する内容 |
| --- | --- |
| `Tag: Select tag` | `v0.1.1` を入力し、新しいタグを作成する項目を選ぶ |
| `Target` | `main` のまま |
| `Release title` | `v0.1.1` |
| `Release notes` | 大きな入力欄に、今回の変更内容を日本語で入力する |

`Release notes` の入力例です。

```text
SD書込の表示を改善しました。

既存の利用者は、アプリの「アップデート確認」から更新できます。
初めて使う方は、Assetsの「ts-sddirecta.exe」をダウンロードしてください。
```

### 5-3. 配布ファイルを添付する

少し下へスクロールし、説明文の入力欄とは別の、次の文字がある点線枠を探します。

> Attach binaries by dropping them here or selecting them.

**この点線枠**をクリックするか、ここへドラッグして、手順3の3ファイルを添付します。

- `ts-sddirecta.exe`
- `latest.json`
- `latest.json.sig`

説明文の入力欄や、その直下の **「Paste, drop, or click to add files」には添付しません。**
そちらは説明文への添付用で、アプリが参照する配布ファイルの登録先ではありません。

3ファイルのアップロードが完了し、名前とファイルサイズが表示されるまで待ちます。
`latest.json` と署名は小さいため、表示単位によっては `0.00 MB` になることがあります。

### 5-4. 公開する

1. `Release label` は **`None`** を選びます。`Pre-release` は選びません。
2. `Set as the latest release` が表示される場合は、有効にします。
3. タグが `v0.1.1` で、3ファイルが揃っていることを確認します。
4. **「Publish release」** を押します。

公開後は、次の状態を確認します。

- `v0.1.1` のページが表示され、`Latest` が付いている。
- `Assets` に、添付した3ファイルが表示されている。
- `Draft` や下書きの警告が表示されていない。

`Source code (zip)` と `Source code (tar.gz)` はGitHubが自動で表示します。
添付した3ファイルと合わせて5件になっていても問題ありません。

## 6. 旧バージョンから更新を確認する

SD処理をしていない状態で、テスト用フォルダーに残した旧バージョンを使います。
必要な利用者データは事前にバックアップしてください。

1. 旧バージョン `0.1.0` を起動します。
2. メニューの「アップデート確認」を押します。
3. 新しい `0.1.1` があるという確認画面が出ることを確認します。
4. **No** を押すと、更新せず元のバージョンで使い続けられることを確認します。
5. もう一度「アップデート確認」を押し、今度は **YES** を押します。
6. 更新後にアプリが再起動したら、「バージョン情報」で `0.1.1` を確認します。
7. CSV・config・input・outputなどの利用者データが保持されていることを確認します。
8. 再度「アップデート確認」を押し、「最新バージョンです。」と表示されることを確認します。

新バージョンの起動直後の異常を、自動で旧版へ戻す機能はありません。
旧exeは、更新したexeの隣の `.ts-sddirecta-update-*` フォルダー内に `previous.exe` として残ります。
このフォルダーは、新バージョンの動作確認が終わるまで保管してください。

## 7. 利用者へ案内する

次の文を、バージョンに合わせて使えます。

```text
ts-sddirecta v0.1.1 を公開しました。

変更内容：SD書込の表示を改善しました。

既にお使いの方：
アプリのメニューから「アップデート確認」を押してください。
更新の確認画面でYESを選ぶと、更新・再起動します。

初めてお使いの方：
https://github.com/shakenyanta/ts-sddirecta-releases/releases/latest
上記ページの「Assets」にある、青い文字の「ts-sddirecta.exe」を押してください。
ダウンロードしたexeを使用するフォルダーに保存して起動します。インストールは不要です。
latest.json、latest.json.sig、Source codeはダウンロード不要です。
```

## 困ったとき

| 状況 | 確認・対処 |
| --- | --- |
| バージョンが一致しないというエラー | 手順2の3ファイルが、すべて同じ値になっているか確認する。 |
| 秘密鍵がない／公開鍵が一致しない | 元の鍵の保存先と `-PrivateKeyPath` を確認する。対処のために新しい鍵へ作り替えない。 |
| ビルドや署名が失敗した | エラーを解消して作成コマンドを再実行する。以前の生成物を誤って公開しない。 |
| 説明欄の下に `We don't support that file type.` が出た | 説明欄への添付エラー。説明欄に入ったファイルリンクを削除し、配布ファイルは手順5-3の点線枠へ添付する。 |
| `Publish release` が薄い緑色で押せない | アップロード完了とタグの選択を確認する。赤い添付エラーが残る場合は、`Save draft` で保存し、`Edit` または鉛筆アイコンから開き直して確認する。 |
| 「更新情報はまだ公開されていません。」と表示される | リリースが公開済みで、最新版のAssetsに `latest.json` があるか確認する。 |
| 更新があるはずなのに「最新バージョンです。」になる | 起動しているexeのバージョンと公開版を確認する。公開版が同じか古い場合は更新されない。`Latest` の付いたリリースも確認する。 |
| 署名・ハッシュの検証で失敗する | 同じ実行で作成した3ファイルか、生成後に内容を変更していないか確認する。 |
| exeを差し替えられない | exeの保存先への書込権限、同じexeの別起動、ファイルの使用中状態を確認する。 |

公開後に不具合を修正する場合も、公開済みファイルを同じ番号のまま差し替えず、
さらに大きいバージョンで新しいリリースを作成します。
